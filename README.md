# Immortalis

LLM-neutral persistent narrative and world-simulation engine (Resurreccion Core).

**Status: Diplomacy Framework Authoritative Core Backbone Foundation.** Builds on the Campaign Continuity Foundation (see [`docs/campaign-package.md`](docs/campaign-package.md)): a campaign can now hold one World Profile, one bounded locus, one released player-character Existence Contract and one active `role.player_character` binding — each written by the specification-backed owner, with dependency direction and owner exclusivity enforced — and it survives save → close → load → continue (see [`docs/canonical-world-foundation.md`](docs/canonical-world-foundation.md)). On top of that, the IM-02 Temporal / Dependency Coordinator lets the campaign advance from a canonical temporal basis toward a bounded target, resolve only the causally engaged dependency cone (exact NOW / named-CLOSE reads, exact stage identity, a transient non-persisted dependency graph), stop with a lawful remainder and — after save, close and load — continue without drift, all through the same commit/journal/package substrate (see [`docs/temporal-foundation.md`](docs/temporal-foundation.md)). There is no turn counter, tick or phase loop, and CAL-01 is not used (the proof is `EXACT-PARTITION`). The IM-04 Population / Cohort adapter then makes Population the sole Unit/Count custodian of a bounded exact ledger (Closing = Opening + typed Entries − Exits), with sparse Cohorts and an externally qualified derived view composed at one temporal basis, an ordinary reconciliation close read AS-OF-DECLARED-CLOSE by dependent consumers, and the PCB-01 due-trigger that makes an engaged-scope reconciliation due only when its frozen conditions hold — again through the same commit/journal/package substrate (see [`docs/population-foundation.md`](docs/population-foundation.md)). CAL-02 is not used (no labor coefficient or default exists). The IM-05 Production owner then makes Production the sole owner of one exact local Reserve's production-side quantity and condition, of the RC-06 claim that protects exactly the material one operation needs (an incompatible claim against already-committed material receives no credit), and of that operation's transformation and sealed Durable Completion Envelope; the operation enters the IM-02 kernel only through its one explicitly declared completion boundary, consumes its input exactly once, completes one durable on one conserved reference and — per F-017 CG-2 — is available for use only after the World-State fallback physical-entity custodian accepts that same reference exactly once, with save, close, load and continue across the unresolved operation (see [`docs/production-foundation.md`](docs/production-foundation.md)). CAL-02 / L-50 is not used (labor and specialist competence are explicitly non-material). The IM-06 Economy owner then fixes one material demand carried by an already-committed Population Unit or Cohort (referenced by identity and pinned version, never copied) together with exactly one Production Request, issues that request into the existing Production machinery, and records realized access only after the existing World-State custodian has accepted the physical result — as one more declared stage of the operation's one temporal object, so Production completion alone is never economic satisfaction and demand can never create supply — with save, close, load and continue across the unresolved request (see [`docs/economy-foundation.md`](docs/economy-foundation.md)). The World-State fallback custodian then lets one already-accepted physical entity undergo one material same-entity locus transition: an already-established external causing result requires it, World-State alone commits the entity's new authoritative current locus exactly once and seals it in ECT-01 under the named Entity Transition Close (one more declared stage with its own earned boundary, never a method), a later consumer reads that committed close without mutating it, the accepted entity and the Production and Economy facts that pin it are never rewritten (the origin stays history and ceases to be current without a rival location truth), and after save, close and load the transition is still pending, still one and never duplicated (see [`docs/entity-continuity-foundation.md`](docs/entity-continuity-foundation.md)). The IM-05 Logistics owner then lets that already-accepted entity move once, single-leg, from one stationary locus to another: an authorized Movement Service Request (its requester's own fact) leads to Logistics' minimum non-agentive movement-service commitment, the entity dispatches, Logistics becomes the sole authoritative current movement locus while the transfer is active (dispatch is not delivery), Logistics establishes delivery completion, World-State commits the destination through the existing ECT-01 seam, and only after that destination commit does Logistics retire the transfer and release the commitment — one engaged boundary, one lawful stage order, one authority answering "where is this entity?" at every durable cut, the same entity unchanged, and a second or competing movement failing closed (see [`docs/logistics-foundation.md`](docs/logistics-foundation.md)). The IM-07 Named-Actor owner then lets a consequential non-PC Named Actor hold one sparse piece of authoritative durable personal mastery (qualitative C / B / A / S or EX, never a number): the capability is established from committed, pinned, foreign causal facts and sealed before any dependent consequence can use it, published at the actor owner's declared capability close as one IM-02 stage inside the engaged object of the consequence that materially requires it, and read by that consequence only AS-OF-DECLARED-CLOSE — with no tick or sweep, no write for a Player Character, an entity under player control or a Population ledger, Population left untouched, and the genuine-uncertainty branch of establishment failing closed because no lawful uncertainty mechanism exists (see [`docs/actor-capability-foundation.md`](docs/actor-capability-foundation.md)). The IM-10 Epistemic Access owner then lets one committed, owner-provided source/carrier context supply one causally real payload to one explicit, bounded, named non-PC recipient: the owner establishes actual receipt as one immutable BOUNDED_SHARED_ACCESS event (the source owner gains no write authority and BROADCAST_EXPOSURE fails closed), reads — where the payload's representational form depends on one — only the already-committed Named-Actor capability AS-OF-DECLARED-CLOSE without ever writing it, and seals the engine-only Sealed Engine Provenance separately from the actor-safe Accessible Content Packet as one IM-02 stage inside the engaged object of the consequence that materially requires it, which reads the packet AS-OF-NOW — receipt, intelligibility and comprehension kept distinct, the packet stopping before any recognition, comprehension, inference, credibility, belief or behaviour, no tick or sweep, a sealed packet never re-formed or improved, and the genuine-uncertainty branch of capability establishment (GitHub Issue #11) neither used nor approximated (see [`docs/epistemic-access-foundation.md`](docs/epistemic-access-foundation.md)). The IM-09 KTI owner then lets one already-committed KTI development object and one already-sealed F-014D BOUNDED_SHARED_ACCESS packet for one named non-PC recipient become one KTI-owned, engine-sealed active managed Transfer Package for that source × recipient × development-object programme: KTI consumes the packet only after it is formed (a basis cannot precede it), only for the recipient it names and an object it supports, and only under the mode-consumer invariant (an unlowered BROADCAST_EXPOSURE is never receipt and fails closed); the package is published at the KTI result close as one IM-02 stage inside the engaged object of the consequence that materially requires it, which reads it only AS-OF-DECLARED-CLOSE — it is workflow state, so receipt never becomes comprehension, competence, reproduction, adoption, belief, institutional uptake or diffusion, a KTI consequence never recreates or improves its source packet, there is no tick or sweep, and GitHub Issue #11 stays untouched (see [`docs/kti-transfer-foundation.md`](docs/kti-transfer-foundation.md)). On top of that, the lawful GIP owner (IM-06) makes one explicitly established continuing institution one stable canonical Institution Identity reference — identity/provenance only (`institution_id`, `identity_label`, the single `continuing` status and, from the twentieth slice, the optional opaque `constitutive_source_ref`): one sealed, create-only slot per institution that reads and depends on nothing foreign, is never auto-created from a label, population, culture, charter, faction, treaty or settlement, is readable by exact identity without GIP write authority, survives save → close → load → continue, converges on retry and fails closed on a conflicting establishment, and carries no office, authority, membership, faction, instrument, asset, KTI, actor, military or economic state and no lifecycle transition (rename, split, merge, abolition, replacement, succession), no GIP tick or stage and no RNG (see [`docs/gip-institution-identity-foundation.md`](docs/gip-institution-identity-foundation.md)). Beneath such a committed institution the same GIP owner can now establish one explicit Office / Authority Locus (thirteenth bounded slice) — the WS-007 §3.2 minimum in its `holder_ref` branch: the authority belongs to the office, not to its holder, so the office carries its authored source reference, competence scope, powers, duties, selection, succession and removal rules and a bare holder reference, copying no authority, personality, capability, knowledge or permission into any actor. It is joined to its institution by exact `institution_id` (never a label) by pinning the committed Institution Identity, is created once at its own exact `institution_id` × `office_id` key, is an owner-`ADVANCING` kind so later lawful transitions can move the same office without a second ledger — while this slice implements initial establishment only and fails every appointment, removal, succession, delegation, amendment or holder replacement closed — is readable by exact key, survives save → close → load → continue, converges on retry, fails closed on a conflicting establishment, and has no delegation, concurrence, veto, conditional authority, exercise, tick, scan or RNG. The fourteenth bounded slice then completes the source's alternate reference branch of that same office — WS-007 §3.2 `holder_ref OR decision_body_ref` — so a new office may point to a decision body instead of one holder: exactly one of the two references (both or neither fail closed; no discriminator field), under the same GIP owner, `ADVANCING` kind, `institution_id` × `office_id` key (the branch is not an identity dimension), exact Institution Identity prerequisite, persistence/recovery path and WS-007 source lineage — new offices carry a truthful current governing-rule citation, and the thirteenth-slice citation is accepted on load only, whole, for a genuine legacy holder office, so existing holder-reference saves load unchanged without migration. `decision_body_ref` is an opaque reference only: it is never resolved against any actor, Autonomous Collective, Population, institution or membership, and no decision-body object, roster, procedure, vote, consent, permission or authority exercise is created or inferred; authority stays at the office, and a holder↔body switch, body replacement, appointment, removal or succession fails closed (see [`docs/gip-office-authority-locus-foundation.md`](docs/gip-office-authority-locus-foundation.md)). The fifteenth bounded slice then adds, beneath one exact already-committed office, the **initial establishment only** of one GIP-owned Scope Binding (WS-007 §5): this office authority is bound to this authored, bounded applicability scope and target condition — `scope_binding_id`, `scope_type`, `scope_ref`, `target_condition`, with optional `inheritance_rule`, `exception_refs[]` and `priority_or_conflict_rule_ref` (one reference) carried exactly as authored. It is one more `ADVANCING` kind of the same GIP owner and facet, keyed `institution_id` × `office_id` × `scope_binding_id` (stored once at its office; never copied per recipient, resident or subject), resting on exactly its parent office (pinned by exact key and version) whose Institution Identity chain must still be committed, creating-once with every later scope, inheritance, exception or conflict change, replacement or resolution failing closed, and surviving save → close → load → continue. `scope_ref`, exceptions and conflicts are opaque and never resolved against any owner, `target_condition` and `inheritance_rule` are carried text that is never parsed or executed, the office's `competence_scope` is untouched, and no Governance Instrument, validity or applicability result, procedure, vote, authority exercise, Administrative Reach, awareness, compliance, Actor/Autonomous Collective choice or institutional KTI consequence is created or inferred (see [`docs/gip-authority-scope-binding-foundation.md`](docs/gip-authority-scope-binding-foundation.md)). The sixteenth bounded slice then adds, beneath one exact already-committed office and one exact already-committed Scope Binding of that same office, the **initial establishment only** of one GIP-owned Governance Instrument core record (WS-007 §4.1): this durable governance rule or act exists, this authority is its source, this is its authority basis, this is its one operative-effect class, this existing Scope Binding says where it is aimed, these are its authored validity entries under the relevant governing orders, and this is its authored lifecycle state — exactly `instrument_id`, `source_authority_ref`, `authority_basis_ref`, singular `operative_effect`, `scope_binding_ref`, `validity_by_order[]` (entries of exactly `governing_order_ref` and `validity_status`) and `lifecycle_status`, with the exact core literals and nothing else. It is one more `ADVANCING` kind of the same GIP owner and facet, keyed by `instrument_id` alone (stored once; `validity_by_order[]` stays inside it; never copied per recipient, subject, place or governing order), resting on exactly its source office and its Scope Binding (each pinned by exact key and version, the binding having to belong to that same office, the Institution Identity chain still committed), creating-once with every later mutation failing closed as unsupported, and surviving save → close → load → continue. `authority_basis_ref` and every `governing_order_ref` are opaque and never dereferenced; validity and lifecycle are authored and never calculated or advanced; the WS-007 §4.3 conditional fields and addressable clauses are unsupported and fail closed; and no enactment, decision procedure, vote, applicability result, promulgation, dissemination, Administrative Reach, implementation, enforcement, compliance or Actor/Autonomous Collective choice is created or inferred (see [`docs/gip-governance-instrument-foundation.md`](docs/gip-governance-instrument-foundation.md)). On top of that, a campaign can hold one Diplomacy-owned External Recognition — the initial authored establishment only (seventeenth bounded slice) of a new IM-06 Diplomacy owner (separate from GIP and Economy) with one External Recognition facet: one recognizer formally holds one scoped external recognition status toward one referent, effective from an authored point, under an authored authority basis and act or instrument — exactly `recognition_id`, `recognizer_ref`, `recognized_referent_ref`, `recognition_scope`, `recognition_status`, `authority_basis_ref`, `effective_from`, optional `withdrawal_or_supersession_condition`, `instrument_or_act_ref`, `provenance_ref`, `continuity_basis`, conditional `successor_rule_ref` and conditional `dependency_refs[]`, WS-008 v1.1 §6 with the §29.2/§29.3 overlay, and nothing else. It is one `ADVANCING` kind keyed by `recognition_id` alone (stored once; directional, never copied as a reciprocal record, per recipient or per observer; no all-pairs scan), creating-once with every later mutation failing closed as unsupported, and surviving save → close → load → continue. The listed `recognition_status` values round-trip exactly but are not a closed set, `continuity_basis` examples are not a closed set, `recognizer_ref` is not restricted to any party class, every reference is opaque and never dereferenced, and `dependency_refs[]` is carried and pinned through the existing group reads and dependencies only where the record is actually derived from mutable implemented owner state. It is not objective existence, control, internal law, recipient awareness, a treaty, negotiation, Instrument, Clause, Binding Entry or Relation Edge, an Actor/ACS choice, a score, or an inference from contact, trade, negotiation or conduct (see [`docs/diplomacy-external-recognition-foundation.md`](docs/diplomacy-external-recognition-foundation.md)). The Diplomacy Externalized Claim / Dispute Core Backbone Foundation (eighteenth slice) then adds the Diplomacy owner's second persistent fact — one externally communicated claim / dispute record under the same Diplomacy owner (one more facet, no second owner), initial authored establishment only. It carries exactly the WS-008 v1.1 §7 identifiers `dispute_id`, `party_refs[]`, `underlying_subject_ref`, `communicated_position_entries[]`, optional `requested_remedy_or_demand`, `interpretation_issue_ref`, `instrument_or_clause_ref` and `adjudication_basis_ref`, `status` and `provenance_ref`, with the §29.3/§29.4 overlay `dependency_refs[]` (conditional) and `effect_on` (conditional; exactly `issuance`, `addressee_receipt` or `instrument_or_setting_specified`, never defaulted), and nothing else. It is one `ADVANCING` kind keyed by `dispute_id` alone (stored once; no copy per party, observer or clause; no all-pairs scan), creating-once with every later mutation failing closed as unsupported, and surviving save → close → load → continue. `party_refs[]` and `communicated_position_entries[]` keep their array shape with no invented minimum, uniqueness or deduplication, position entries carry no invented schema, `status` is not a closed set, every reference is opaque and never dereferenced, and `dependency_refs[]` is pinned through the existing group reads and dependencies only where the record is actually derived from mutable implemented owner state. Diplomacy owns only the fact that the position was externally communicated: the underlying claim stays with its authoritative owner, no private belief, future behavior or objective truth is inferred, and no Epistemic receipt, Relation Edge, Instrument, Clause or Binding Entry is created (see [`docs/diplomacy-externalized-claim-dispute-foundation.md`](docs/diplomacy-externalized-claim-dispute-foundation.md)). The Diplomacy Relation Edge Authoritative Core Backbone Foundation (nineteenth slice) then adds the Diplomacy owner's third persistent fact — one sparse, materially continuing external relation under the same Diplomacy owner (one more facet, no second owner), initial authored establishment only. The GIP Institution Identity Constitutive Source Reference Foundation (twentieth slice) then lets an authored initial Institution Identity optionally carry the exact WS-007 §3.1 `constitutive_source_ref` — one optional, singular, opaque reference carried exactly as authored, in the existing GIP opaque-reference representation. ## Governing specification

- Implementation package: F-027 v1.0 — see [`spec/f027/spec-lock.json`](spec/f027/spec-lock.json) (exact Notion pins). "Latest Notion" is never an implicit build input.
- Rules for contributors and agents: [`IMPLEMENTATION_CHARTER.md`](IMPLEMENTATION_CHARTER.md), [`CONTRIBUTING.md`](CONTRIBUTING.md), [`SECURITY.md`](SECURITY.md).
