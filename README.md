# Immortalis

LLM-neutral persistent narrative and world-simulation engine (Resurreccion Core).

**Status: GIP Office / Authority Locus Backbone Foundation.** Builds on the Campaign Continuity Foundation (see [`docs/campaign-package.md`](docs/campaign-package.md)): a campaign can now hold one World Profile, one bounded locus, one released player-character Existence Contract and one active `role.player_character` binding — each written by the specification-backed owner, with dependency direction and owner exclusivity enforced — and it survives save → close → load → continue (see [`docs/canonical-world-foundation.md`](docs/canonical-world-foundation.md)). On top of that, the IM-02 Temporal / Dependency Coordinator lets the campaign advance from a canonical temporal basis toward a bounded target, resolve only the causally engaged dependency cone (exact NOW / named-CLOSE reads, exact stage identity, a transient non-persisted dependency graph), stop with a lawful remainder and — after save, close and load — continue without drift, all through the same commit/journal/package substrate (see [`docs/temporal-foundation.md`](docs/temporal-foundation.md)). There is no turn counter, tick or phase loop, and CAL-01 is not used (the proof is `EXACT-PARTITION`). The IM-04 Population / Cohort adapter then makes Population the sole Unit/Count custodian of a bounded exact ledger (Closing = Opening + typed Entries − Exits), with sparse Cohorts and an externally qualified derived view composed at one temporal basis, an ordinary reconciliation close read AS-OF-DECLARED-CLOSE by dependent consumers, and the PCB-01 due-trigger that makes an engaged-scope reconciliation due only when its frozen conditions hold — again through the same commit/journal/package substrate (see [`docs/population-foundation.md`](docs/population-foundation.md)). CAL-02 is not used (no labor coefficient or default exists). The IM-05 Production owner then makes Production the sole owner of one exact local Reserve's production-side quantity and condition, of the RC-06 claim that protects exactly the material one operation needs (an incompatible claim against already-committed material receives no credit), and of that operation's transformation and sealed Durable Completion Envelope; the operation enters the IM-02 kernel only through its one explicitly declared completion boundary, consumes its input exactly once, completes one durable on one conserved reference and — per F-017 CG-2 — is available for use only after the World-State fallback physical-entity custodian accepts that same reference exactly once, with save, close, load and continue across the unresolved operation (see [`docs/production-foundation.md`](docs/production-foundation.md)). CAL-02 / L-50 is not used (labor and specialist competence are explicitly non-material). The IM-06 Economy owner then fixes one material demand carried by an already-committed Population Unit or Cohort (referenced by identity and pinned version, never copied) together with exactly one Production Request, issues that request into the existing Production machinery, and records realized access only after the existing World-State custodian has accepted the physical result — as one more declared stage of the operation's one temporal object, so Production completion alone is never economic satisfaction and demand can never create supply — with save, close, load and continue across the unresolved request (see [`docs/economy-foundation.md`](docs/economy-foundation.md)). The World-State fallback custodian then lets one already-accepted physical entity undergo one material same-entity locus transition: an already-established external causing result requires it, World-State alone commits the entity's new authoritative current locus exactly once and seals it in ECT-01 under the named Entity Transition Close (one more declared stage with its own earned boundary, never a method), a later consumer reads that committed close without mutating it, the accepted entity and the Production and Economy facts that pin it are never rewritten (the origin stays history and ceases to be current without a rival location truth), and after save, close and load the transition is still pending, still one and never duplicated (see [`docs/entity-continuity-foundation.md`](docs/entity-continuity-foundation.md)). The IM-05 Logistics owner then lets that already-accepted entity move once, single-leg, from one stationary locus to another: an authorized Movement Service Request (its requester's own fact) leads to Logistics' minimum non-agentive movement-service commitment, the entity dispatches, Logistics becomes the sole authoritative current movement locus while the transfer is active (dispatch is not delivery), Logistics establishes delivery completion, World-State commits the destination through the existing ECT-01 seam, and only after that destination commit does Logistics retire the transfer and release the commitment — one engaged boundary, one lawful stage order, one authority answering "where is this entity?" at every durable cut, the same entity unchanged, and a second or competing movement failing closed (see [`docs/logistics-foundation.md`](docs/logistics-foundation.md)). The IM-07 Named-Actor owner then lets a consequential non-PC Named Actor hold one sparse piece of authoritative durable personal mastery (qualitative C / B / A / S or EX, never a number): the capability is established from committed, pinned, foreign causal facts and sealed before any dependent consequence can use it, published at the actor owner's declared capability close as one IM-02 stage inside the engaged object of the consequence that materially requires it, and read by that consequence only AS-OF-DECLARED-CLOSE — with no tick or sweep, no write for a Player Character, an entity under player control or a Population ledger, Population left untouched, and the genuine-uncertainty branch of establishment failing closed because no lawful uncertainty mechanism exists (see [`docs/actor-capability-foundation.md`](docs/actor-capability-foundation.md)). The IM-10 Epistemic Access owner then lets one committed, owner-provided source/carrier context supply one causally real payload to one explicit, bounded, named non-PC recipient: the owner establishes actual receipt as one immutable BOUNDED_SHARED_ACCESS event (the source owner gains no write authority and BROADCAST_EXPOSURE fails closed), reads — where the payload's representational form depends on one — only the already-committed Named-Actor capability AS-OF-DECLARED-CLOSE without ever writing it, and seals the engine-only Sealed Engine Provenance separately from the actor-safe Accessible Content Packet as one IM-02 stage inside the engaged object of the consequence that materially requires it, which reads the packet AS-OF-NOW — receipt, intelligibility and comprehension kept distinct, the packet stopping before any recognition, comprehension, inference, credibility, belief or behaviour, no tick or sweep, a sealed packet never re-formed or improved, and the genuine-uncertainty branch of capability establishment (GitHub Issue #11) neither used nor approximated (see [`docs/epistemic-access-foundation.md`](docs/epistemic-access-foundation.md)). The IM-09 KTI owner then lets one already-committed KTI development object and one already-sealed F-014D BOUNDED_SHARED_ACCESS packet for one named non-PC recipient become one KTI-owned, engine-sealed active managed Transfer Package for that source × recipient × development-object programme: KTI consumes the packet only after it is formed (a basis cannot precede it), only for the recipient it names and an object it supports, and only under the mode-consumer invariant (an unlowered BROADCAST_EXPOSURE is never receipt and fails closed); the package is published at the KTI result close as one IM-02 stage inside the engaged object of the consequence that materially requires it, which reads it only AS-OF-DECLARED-CLOSE — it is workflow state, so receipt never becomes comprehension, competence, reproduction, adoption, belief, institutional uptake or diffusion, a KTI consequence never recreates or improves its source packet, there is no tick or sweep, and GitHub Issue #11 stays untouched (see [`docs/kti-transfer-foundation.md`](docs/kti-transfer-foundation.md)). On top of that, the lawful GIP owner (IM-06) makes one explicitly established continuing institution one stable canonical Institution Identity reference — identity/provenance only (`institution_id`, `identity_label`, the single `continuing` status): one sealed, create-only slot per institution that reads and depends on nothing foreign, is never auto-created from a label, population, culture, charter, faction, treaty or settlement, is readable by exact identity without GIP write authority, survives save → close → load → continue, converges on retry and fails closed on a conflicting establishment, and carries no office, authority, membership, faction, instrument, asset, KTI, actor, military or economic state and no lifecycle transition (rename, split, merge, abolition, replacement, succession), no GIP tick or stage and no RNG (see [`docs/gip-institution-identity-foundation.md`](docs/gip-institution-identity-foundation.md)). Beneath such a committed institution the same GIP owner can now establish one explicit Office / Authority Locus (thirteenth bounded slice) — the WS-007 §3.2 minimum in its `holder_ref` branch: the authority belongs to the office, not to its holder, so the office carries its authored source reference, competence scope, powers, duties, selection, succession and removal rules and a bare holder reference, copying no authority, personality, capability, knowledge or permission into any actor. It is joined to its institution by exact `institution_id` (never a label) by pinning the committed Institution Identity, is created once at its own exact `institution_id` × `office_id` key, is an owner-`ADVANCING` kind so later lawful transitions can move the same office without a second ledger — while this slice implements initial establishment only and fails every appointment, removal, succession, delegation, amendment or holder replacement closed — is readable by exact key, survives save → close → load → continue, converges on retry, fails closed on a conflicting establishment, and has no decision body, delegation, concurrence, veto, conditional authority, exercise, tick, scan or RNG (see [`docs/gip-office-authority-locus-foundation.md`](docs/gip-office-authority-locus-foundation.md)). No persistence/deployment provider, host protocol, migration, routing, carriers, message travel, broadcast, capacity, market, price, currency, credit, KTI competence, reproduction, adoption or diffusion, personality or other Named-Actor behavior, source-stock dynamics or other gameplay mechanic exists, and every F-027 open gate remains open.

## Governing specification

- Implementation package: F-027 v1.0 — see [`spec/f027/spec-lock.json`](spec/f027/spec-lock.json) (exact Notion pins). "Latest Notion" is never an implicit build input.
- Rules for contributors and agents: [`IMPLEMENTATION_CHARTER.md`](IMPLEMENTATION_CHARTER.md), [`CONTRIBUTING.md`](CONTRIBUTING.md), [`SECURITY.md`](SECURITY.md).
- Notion is the design/governance source of truth; GitHub is the implementation/version/review source of truth.

```sh
pnpm run lint
pnpm run typecheck
pnpm run check:spec
pnpm test            # or test:unit | test:contract | test:conformance | test:security | test:integration
pnpm run ci          # all of the above
```
