# Initial Local Population and Residency Cohort Admission Foundation

> **OOC DEVELOPMENT / SCENARIO INSTRUMENTATION.** This is an out-of-character local console path that lets an operator author, confirm and commit **ONE disjoint resident Population ledger and ONE Population-owned residency-indexed Cohort reference** at an already committed World-State world and locus of a fresh, operator-confirmed, **pre-play** scenario that already holds a canonical time, **before any player character is bound**. It is **mechanism only**: two opening setting facts under the Population owner. It is not a Population owner, not a population generator, not demography, not a Named Actor or any actor, not a mind, belief, loyalty, culture or social truth, not a labour supply, labour rate or yield, not perception or knowledge, not a resource collection, not an origin event, not movement or migration, not a close and not a Cohort outcome. It creates no world, locus, source, game actor, relationship or character, and advances no time.

Bounded implementation slice (`@immortalis/operator`: `establish-population`), composed from the **already implemented** Population owner operations `PopulationAdapter.establishLedger` and then `PopulationAdapter.instantiateCohort`. No `packages/contracts`, `packages/engine`, `packages/protocol` or `packages/testkit` module changed; there is no new Population operation, owner, facet, schema, key class, lifecycle, persistent receipt format, status gate or general population initializer. The shipped binary registers no owner extension.

## The command

```
immortalis-operator establish-population --campaign <dir> --campaign-id <id> --population-file <file> [--operator-dir <dir>] [--reclaim-stale-lock]
```

The population file is one strict JSON document:

```
{ "format": "immortalis-initial-population", "format_version": 1,
  "ledger": { "ledger_id", "unit_class", "world_id", "locus_id", "units": [ { "unit_id", "residence", "presence", "burden_allocation" } ], "point": { "unit", "value" } },
  "cohort": { …one full strict CohortRef, every field explicit… } }
```

`ledger` is exactly the unchanged `EstablishLedgerInput` and `cohort` exactly the unchanged `CohortRef` (`packages/contracts/src/population.ts`). Every object is strict and every field required, with nothing defaulted (a unit's `burden_allocation` is `null` when none is recorded, and is never assumed): the file can carry no owner, facet, version, count, member list, consumed envelope, basis stamp, close, Cohort result, labour or birth rate, probability, actor reference, publication label or "confirmed" claim (each is an unknown field and is refused). The count is the owner's: `{ semantics: "EXACT", count: units.length }`, never an input.

**This path admits one bounded Cohort family**, as its own eligibility conditions (the Population owner's admission still judges everything again): a Population-owned criterion with no reference (`{ owner: "population", ref: null }`); exactly one indexed fact, `RESIDENCE`, with membership basis `INDEXED_FACT_AT_PLACE`; scope `{ ledger_id, place }` naming this ledger and the selected established locus; form `OVERLAPPING_VIEW` with overlap `OVERLAPPING`; EXACT cardinality; temporal read `AS-OF-DECLARED-CLOSE` at the Population ordinary close basis; `CURRENT-ONLY` retention; the single retirement predicate; invalidators exactly the ledger. The Cohort's unit class is the ledger's. A presence- or burden-indexed Cohort, an externally qualified one, a labour claim, a named subset, a partition, a bounded or unquantified cardinality, rates or probabilities have no representation here. The ledger must hold at least one unit and no unit identifier twice (a unit is counted once). Units may be authored in any order: they are read in the owner's order (by `unit_id`), and that order is what is shown, confirmed and committed.

The file is read once, from one open descriptor: a regular file (not a link) owned by the invoking OS user and writable by nobody else, of bounded size. What was read is what is shown, confirmed and committed; a file changed afterwards cannot change it.

**The units are authored opening premises, not a conclusion.** Their distinct residence, presence and burden allocation say where the operator places them at the opening; they assert nothing about anyone's culture, loyalty, behaviour or labour. A Population Unit is not a Named Actor: nothing here creates an actor, a mind or a decision.

## Sequence

1. **Read and check the file** (above), including the owner's own ledger shape. Nothing is asked of the console if it is refused.
2. **Open the existing package** for the local operator (the usual OS-user verification, the package lock, journal replay and canonical integrity). This command **never creates, adopts, repairs or clears** a package: a missing or foreign directory, or another campaign identity, is `SESSION_UNAVAILABLE`.
3. **Read the established locality from canon** (`establishedLocality`, read-only, shared with the earlier commands): the ORIGINAL world, the first locus and the first source that one `establish-locality` setup identity committed, each still the version-1 fact that setup wrote. None held → `LOCALITY_NOT_ESTABLISHED`; held but since advanced → `PRE_PLAY_CLOSED`.
4. **If both stages of this identity already committed** (a repeat, a lost reply, a restart): judge them on the immutable committed record. When each record is exactly the one write of this proposal, with the exact derived value and reads of — and dependencies on — exactly what it was established against (the world and locus for the ledger; the ledger at version 1 for the Cohort), they are verified and reported **without asking again and without a write**. A stage committed with other content, or whose fact is not held, or a Cohort committed without its ledger, is `LEDGER_CONFLICT` / `COHORT_CONFLICT`. A ledger or Cohort that Population has since advanced beyond version 1 (a close has been resolved) is `PRE_PLAY_CLOSED`, never "established". Replay is pre-play only: once a player character is bound, an identical rerun is `PRE_PLAY_CLOSED` with no prompt and no write.
5. **Pre-play and consistency refusals**, all before the console is asked and with no write: a bound player character → `PRE_PLAY_CLOSED`; a world other than the established world, or a locus that is not committed, or not one the operator-confirmed scenario established at version 1 (the first locus `establish-locality` wrote, or a **complete** additional locality's locus), → `POPULATION_NOT_AT_LOCALITY`; the ledger key, or the Cohort key, already held by another identity, or **any other Population ledger already held in the campaign**, → `LEDGER_CONFLICT` / `COHORT_CONFLICT`. The last is this path's own fail-closed condition (one initial Population per campaign by this path), not a Population rule: the sources fix no inter-ledger disjointness law and none is invented here.
6. **Require the existing canonical time** (a ledger stage only). The opening state is established **at** a canonical time, and this command creates, chooses and advances none. The Temporal owner's committed state must exist (`TIME_NOT_ESTABLISHED` otherwise, a missing prerequisite — never a success), and the ledger's `point` must equal that canonical time exactly, in the same unit (`TIME_MISMATCH` otherwise). A resumed Cohort stage is judged on its already committed ledger alone. The shipped operator tooling has no path that establishes canonical time; the disposable tests establish it through the Temporal owner's own operation as a scenario premise, and a real scenario needs its own lawful time origin, which this slice does not provide.
7. **Prove the owner path admits it**: the committed world and locus are republished on a scratch package that is then removed, and the ledger and then the Cohort are run through the genuine Population adapter. A refusal is `INVALID_POPULATION` with nothing written. The scratch package is never reused.
8. **Confirm, once.** The whole proposal is shown (authored text JSON-quoted so a control sequence cannot rewrite the console; identifiers carry no control character) with what it does **not** do and the stages still to commit. The operator types `establish-population <fresh challenge>` on the very next line; anything else, a stale or pre-typed line, another verb's phrase or end of input declines and nothing has been written. The confirmation is a one-time token bound to the verb and the exact subject (campaign, established locality, population identity, pending stages and the full ledger and Cohort).
9. **Commit in dependency order** (`PROGRESS ledger COMMITTED …`, then `PROGRESS cohort COMMITTED …`): the ledger through `PopulationAdapter.establishLedger`, and only after that fact is committed the Cohort through `PopulationAdapter.instantiateCohort`. The owner derives the ledger (count, `DISJOINT_RESIDENT_POPULATION`, nothing consumed, an `ESTABLISHMENT` basis stamp at the point) and stores the Cohort reference with **`result: null`**; both are published under owner **`population`**, facet **`population_state`**, at create version 1. The operator never writes through any raw `store.commit`, never writes a count, a member list, a close or a Cohort result, and never engages a reconciliation.
10. **Verify on a fresh reopen.** The package is closed and reopened through the engine's owner-verified open; each new fact's key, owner/facet, version 1, typed value and committed provenance are compared with the confirmed proposal (the Cohort must still hold no result), **every fact the campaign held before is compared with its pre-commit self** (key, owner, facet, value, version, provenance — the canonical time included), and the fact count and revision are exactly the expected number greater. Only then is `POPULATION_READY` reported.

Statuses: `POPULATION_READY`, `POPULATION_INCOMPLETE`, `POPULATION_OUTCOME_UNKNOWN`, `POPULATION_REFUSED`, `POPULATION_VERIFICATION_FAILED`, `LOCALITY_NOT_ESTABLISHED`, `PRE_PLAY_CLOSED`, `TIME_NOT_ESTABLISHED`, `TIME_MISMATCH`, `POPULATION_NOT_AT_LOCALITY`, `LEDGER_CONFLICT`, `COHORT_CONFLICT`, `SESSION_UNAVAILABLE`, `DECLINED`, `INVALID_POPULATION`, `POPULATION_FILE_UNTRUSTED`, `POPULATION_FILE_UNREADABLE`. `POPULATION_READY` means exactly: both facts are committed under this identity at version 1, verify, and nothing earlier changed. A ledger committed without its Cohort is `POPULATION_INCOMPLETE` (a known refusal of the second stage) or `POPULATION_OUTCOME_UNKNOWN` — **never** a success — until the same command is rerun to finish it.

## Identity, convergence and fail-closed

The service authors only the technical publication identities and derives them from the exact authored content, never from a clock or a random value: `<id>` is a hash of the campaign identity, the ledger and the Cohort, giving for each stage `<name>` ∈ {`ledger`, `cohort`} group `operator-initial-population:<id>:<name>`, intent `operator-initial-population-intent:<id>:<name>` and cause `operator-initial-population-cause:<id>`.

- **The same confirmed proposal always reaches the same identities.** A retry after a crash or a lost reply replays what committed (RC-16, by the store's own identity check) and finishes what did not, **resuming only the exact original durable request**; it never writes a second, rerolled, reordered or altered ledger, unit or Cohort, and never changes a completed initial population.
- **Any different content under the same ledger or Cohort identifier meets the committed key and is refused**; committed facts are never replaced. A different proposal offered while a ledger waits for its Cohort is refused, never substituted; a Cohort another writer committed under the waiting ledger's key is a conflict, neither adopted nor replaced.
- **No retained state is added.** There is no new pin, receipt or ledger format: the committed record in the package is the only memory of what committed (the session still opens the existing owner-only retained-intent directory, unchanged).
- **Once pre-play ends, setup is closed**, replay included: a bound player character, an advanced locality fact, or a ledger or Cohort Population has since reconciled, all refuse.

## Recovery

The package's own file lock and durable-write order are used unchanged. A kill leaves the lock; it is refused until the operator explicitly passes `--reclaim-stale-lock`, which the engine honours only for a provably dead holder. Tests interrupt before the ledger, after the ledger and before the Cohort, after the Cohort and before the reply (a lost acknowledgement), by a known refusal of each stage, by a failed reopen after the close, by a real `SIGKILL` of the shipped binary at the console, after the ledger and after the Cohort, and by a failure before **and** after every mutating filesystem operation of the whole command; each converges on the uninterrupted campaign (equal head, state and journal hashes), with a Cohort never present without its ledger and no duplicated unit.

## The disposable witness (tests only)

`tests/integration/initial-population-foundation.test.ts` then engages **Population's own existing ordinary reconciliation close** on a disposable campaign, through the Temporal coordinator, the genuine `populationStageProvider` and a Temporal object whose declaration is `populationReconcileDeclaration` with a Population-owned criterion only — no criterion owner and no causal register is read, and no consequence envelope is invented. The close resolves at a later canonical time than the ledger's opening point, and **Population itself** derives the Cohort's exact members and count from the authored units' residence (the test asserts the independently computed residents of the locus, never the outcome as a source): units merely present at the locus, or resident elsewhere, are not members; different authored distributions yield different derived views; before the close the Cohort holds no result and the existing typed read answers `VIEW_UNAVAILABLE`; fabricated closes, caller-set counts, forged Cohort results and another owner's writes are refused. The Temporal registration and the canonical-time establishment in those tests are test helpers and are not shipped as canon-writing producers. **A scripted close proves the Population owner's arithmetic over authored units; it does not prove live NPC action, social behaviour, labour or any actor.** The actor state, stimulus, cognition and mandate chain remains an **EXTERNAL PREREQUISITE MISSING** and is not claimed.

## Security

The full proposal (identifiers, places and every unit) is shown only on the operator's own console and held only in the owner-verified package. It is not written to the retained-state directory, and no host-facing surface (referee, player-view, observe-request or advance-request MCP servers, the protocol package) imports or names this command. **No MCP, phone or client Population list, search or creation tool is added.** No model, MCP client or command-line flag can attest the human confirmation. The module has no network, child-process, environment or global-state access.
