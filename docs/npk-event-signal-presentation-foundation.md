# NPK Active-PC Event-Signal Presentation Foundation

Thirty-sixth bounded slice, built on the I-001 Active-PC Event-Signal Projection foundation (`docs/i001-event-signal-projection-foundation.md`, PR #37) and, through it, the Epistemic Access, Temporal and Canonical World foundations. **One lawful current `EventSignalProjection` produced by the existing IM-13 path can now produce one disposable, non-canonical IM-14 / NPK presentation result.** The presentation layer consumes the projection. It does not re-resolve the world, re-read Epistemic state or create a second truth source, and it renders no prose of its own.

Governing lock: `spec/f027/spec-lock.json` (F-027 v1.0 composed with F-027-CD1 v1.0). No source pin, Runtime Contract snapshot, open gate or acceptance status changed. **CAL-\* stay unused: no number, threshold, window, score, roll, prior or default exists anywhere in this slice.**

## The rendering

1. **The projection is the only input.** The value is parsed through the strict `EventSignalProjectionSchema`: only a value shaped exactly as IM-13 produces one is rendered. A refusal result, a success wrapper, a request, a store, a packet, an event, sealed provenance, a projection carrying any extra (smuggled) field, or any malformed value is refused. An unavailable or non-current projection (which IM-13 never produced) therefore never becomes a presentation opportunity by another route. The composed path in the tests is `derive → (projection ok ? present : the IM-13 refusal)`.
2. **Carried exactly.** The contact channel, the Presented Source Attribution, the referent and the content are the projection's own values, byte for byte. A false or stale presented attribution is rendered as presented and never corrected against hidden truth (I-001 §10); a hidden-sounding payload ("Unknown", "Locked", a key-shaped string) is just text.
3. **One fixed presentation order** (the one choice the presenter makes, which the NPK envelope leaves to NPK): contact, then the attribution when the carrier presented one, then referent, then content. An absent attribution has **no element** and no placeholder: nothing is announced as "unknown" (I-001 §4 step 3).
4. **Nothing is added.** No connective prose, label, heading, register, mode, cadence, affect, urgency, interpretation, comprehension, belief, memory, motive, diagnosis, true source, unseen cause or time. The element names (`CONTACT`, `PRESENTED_ATTRIBUTION`, `REFERENT`, `CONTENT`) are structure tags for the host surface, not display strings. Every text value in the result is a received value; a conformance test pins the module's only string literals.

Every refusal is the **same** opaque refusal IM-13 uses (`PROJECTION_UNAVAILABLE` / `"no projection is available"`, no details), so the path's refusal for any cause is byte-identical to IM-13's and reveals neither the cause nor whether hidden state exists. The presenter has no branch on anything but the shape of the one value it is handed, so it adds no read, no concealed-state-dependent control flow and no new timing channel beyond IM-13's (wall-clock constant time is, as in the predecessor, not claimed; that belongs to the host/protocol boundary).

## Interpretive anchor for review

The presenter's output shape is the one design decision of this slice. The frozen NPK envelope gives NPK the "presentation order", "descriptive selection" and "player-facing phrasing" of material that an authority has already admitted, and forbids inventing knowledge, motive, cognition or world facts. This slice takes the strictest neutral reading: it makes the presentation order (and only that) NPK's choice and produces **no phrasing at all**, so no frozen phrasing, voice or register rule was needed or invented. A richer renderer (scene prose, Narrator Performance, Interface/Report modes) belongs to later work that owns that material; this contract can be wrapped by it without change.
