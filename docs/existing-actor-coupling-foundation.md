# Existing-Actor World-State Coupling Anchor Foundation

Thirtieth bounded slice, built on the Canonical World Identity & Owner Foundation (`docs/canonical-world-foundation.md`: the World Profile and locus), the World-State fallback custody and entity-continuity foundations (`docs/entity-continuity-foundation.md`), the Named-Actor capability backbone (`docs/actor-capability-foundation.md`) and the existing-actor I-002 pre-binding compilation (`docs/existing-actor-compilation-foundation.md`). The engine could already establish that an actor exists and that a world/locus exists. It can now also hold the **authoritative World-State fact that one already-existing, lawfully non-PC actor is currently coupled to one established locus of one established world**.

This is a **prerequisite only**. It performs no PC binding, no ownership handover and no capability movement.

Governing lock: `spec/f027/spec-lock.json` (F-027 v1.0). No source pin, Runtime Contract snapshot, open gate or acceptance status changed.

**Result: the sources compose; no genuine contradiction was found, and no pin was moved.** The clauses this slice rests on:

- **Who owns an actor's physical location.** F-014A v3.3 §6 (Two-Target Write Rule): "injury, death, custody, **physical location**, office holding, economic holding and other world/domain state attach to the true affected entity/domain" — never to the holder/actor-side record. I-002 §4.3: "Position, local damage, local condition and other world-locus differences belong to Insertion/world/runtime owners and do not force I-002 per-locus records." IR §17: "world placement/overlap → World owner". I-002 v2.4 "Embodiment Before Operative PC Control": "the body/substrate remains real world state … independent actors remain independently owned".
- **Which world owner.** WG "Ownership Guards": World-State is the fallback custodian of objective physical/entity facts "only where no more-specific authoritative owner exists for the exact fact", carrying "physical/entity identity or reference … continuity-dependency binding …", and may own "world-side environmental, geographic, topological and other general world-state facts not owned by a more specific subsystem". No more-specific owner of an actor's current locus exists in the repository or the sources read (the Named-Actor owner holds capability facts only; I-002 explicitly excludes locus; Insertion owns only the binding transition).
- **Why it is a prerequisite and not a handover.** The Handover Contract's "Single Commit Point": "Before that commit, the current owner remains writable." IR §5 item 3 lets Insertion consume an "authoritative world/PC fact already established"; this slice establishes that world fact and consumes none of it. WG's own existing-actor → PC clause ("fallback intrinsic entity facts that fall within I-002's Existence Contract migrate to I-002 with no overlapping writable interval") applies at the binding commit, which is not implemented.

**Judgment recorded, not a contradiction.** No source states in so many words that "an actor's current locus coupling" is a named World-State record, or fixes its serialization. The assignment above is reasoned from the F-014A §6 / I-002 §4.3 / IR §17 ownership statements plus the WG fallback clause, and follows the precedent of the Entity Transition Close (the same custodian holding the same kind of locus fact for a physical entity). If Blue would rather assign actor locality to a different owner, that is a registry decision to make; no source here supports one.

## Behavior, end to end

1. The Named-Actor owner establishes the actor's capability facts as before (this is what makes the actor "already existing" in this repository).
2. `coupleExistingActor` commits **one** fact at `world-state/actor/<id>/coupling`. The pinned facts are untouched.
3. The prior owner **stays writable**: further Named-Actor establishments and capability closes for the identity are admitted exactly as before (`actorBoundaryViolation` is consulted, never changed).
4. No binding, Existence Contract or PC capability is written. The binding slot stays NULL. The coupled actor may still be compiled into I-002 form (before or after), and ordinary activation still refuses that compilation.
5. A second coupling of the same actor — same locus, another locus, another world — is a version conflict; an amendment is `AMENDMENT_NOT_SUPPORTED`; any sibling key is `KEY_NOT_ADMITTED`.
6. Everything survives save → close → load, with convergence on the uninterrupted run from every durable cut; a lost reply converges by identity (RC-16).

Fresh-PC activation, the Production durable/entity path (acceptance, entity-transition, Economy, Logistics), PR #31's compilation behavior and every existing ownership boundary are unchanged.

## Construction decisions that are technical encodings, not new semantics

- **Slot per actor, not per world.** The sources require exactly one authoritative current locus; a per-world slot would allow two. The key therefore embeds only the actor identity.
- **Sealed, create-only.** Moving an actor is a later successor mechanism (like the entity transition's chained record); this slice does not invent one. A second coupling is a conflict, never a sibling truth.
- **"Already existing" evidence is the Named-Actor capability facts**, the only authoritative already-existing non-PC actor state this repository holds (the same two source kinds the existing-actor compilation accepts, shared by one function so they cannot drift). Widening the sources to another owner is a later, source-backed step.
- **`pinned_versions` accepts `0`** (like the binding's pins) so a missing world or locus surfaces as `PREREQUISITE_MISSING` at admission; no committed coupling can carry `0`.
- **Guard on the Existence Contract path.** `checkExistenceContract` additionally refuses a fresh contract for an already-coupled identity. This is the only edit to a predecessor admission rule; it affects no identity that has no coupling, so every existing campaign and the fresh-PC path behave byte-for-byte as before.
- **Shared source statement.** The pin loop of `existingActorCompilationViolation` moved, unchanged, to `existingActorSourceViolation` (`actor/derive.ts`) so the compilation and the coupling use one statement. Its messages and results are identical.

## Not implemented (fail closed; none resolves an open gate)

The Existing-Actor → PC Role Registry handover (the binding schema still represents only the first `ACTIVATION`); consuming this coupling as an insertion basis; capability ownership transfer or PC capability carry-forward; unresolved inherited capability resolution and Causal Draw / world-prior work (`UNRESOLVED` stays unrepresented); PC release, succession, replacement, fork or deactivation; Intrinsic Amendment Events; F-014D `BROADCAST_EXPOSURE`; relocating a coupled actor; broad actor behavior; a generic person/location/entity subsystem; any new RC-07 or cross-owner transaction semantics; provider, database or deployment work.

## Residuals

- The coupling is verified for identity, ownership and provenance only; whether the locus is a _sensible_ place for the actor is not judged (no source supplies one).
- The Handover Contract's binding-time migration of fallback intrinsic entity facts to I-002 is not exercised, because no coupling field is an I-002 Existence Contract field (locus is excluded from I-002 by §4.3); whether a later handover slice must additionally re-express the coupling at the binding commit is that slice's decision.
- `verifyExistingActorCouplingIntegrity`, like the other verifiers, lists all facts once per open (diagnostic path, CAL-06), and returns immediately when no coupling exists.
