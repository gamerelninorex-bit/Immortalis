### 2.4 SI_SUBDAY_V1 conversion and safe arithmetic

`siSubdayV1Target(basis: CanonicalTime, value: number, unit: "second"|"minute"|"hour"): Result<CanonicalTime, "INPUT_INVALID">` (pure, CANDIDATE):

```text
converted = value * SI_SUBDAY_V1_SECONDS[unit]
targetVal = basis.value + converted
refuse unless Number.isSafeInteger(converted) && Number.isSafeInteger(targetVal) && converted >= 1
return { unit: basis.unit, value: targetVal }        // unit carried verbatim, never mapped (A5 "no arbitrary unit mapping")
```

- **Source of the factors.** A5 and A9 supply them, and the P1a/P1b fixtures confirm them: "T0 second:100 ... 3 seconds → Derived target 103" and "10 minutes → SI_SUBDAY_V1 target 700" (v0.6 §7).
- **Bounds come from existing code only.**
  - `basis.value ∈ [0, 2^53−1]`, because `CanonicalTimeSchema` enforces `int().nonnegative().max(Number.MAX_SAFE_INTEGER)` (`temporal.ts:51`).
  - `value ∈ [1, 2^53−1]`.
  - The target must satisfy the same `CanonicalTimeSchema` bound.
  - Exactness: the guard is `Number.isSafeInteger` on both the product and the sum. This is the existing pattern at `engine/src/pc-collection/derive.ts:446–452` ("the derived completion is not representable"). IEEE rounding is monotonic, so any exact result above 2^53−1 rounds to a value of at least 2^53 and fails the guard, and any result at or below 2^53−1 is exact.
  - The resulting maximum `value` at basis 0 is 9 007 199 254 740 991 seconds, 150 119 987 579 016 minutes and 2 501 999 792 983 hours. In general it is `floor((2^53−1 − basis.value) / factor)`.
- **No other cap.** A9 says "No arbitrary numeric wait cap is adopted", and the static public horizon limit of v0.6 §5.1 belongs to the B1 catalogue. OSQ-9 (BLUE): "no invented 86,400-second cap. SI_SUBDAY_V1 fixes conversion factors for second/minute/hour, safe exact arithmetic and present source-authorized time/unit; it does not itself ratify an arbitrary duration ceiling. This does not waive actual horizon/owner/choice checks." Those checks are B1's.
- **What the unit means.** The result is in canonical coordinate units. Reading those units as seconds is valid only after B1's category-8 check that the clock origin is one SI second per unit (A17 §5). B0 never reads or infers this, and it never branches on the spelling of `basis.unit` (A17 §2).

## 6. What B0 does not do, and test labelling

B0 does none of the following:

- It opens no transaction and writes nothing: no store, coordinator, journal or ledger, no durable writer, and no `TransactionAuthority` or `ResolutionTransaction` value (A12 §1, §3).
- It performs no read of any kind. That includes no T0 category 1–8 read. In particular it does not read `temporal/origin`, does not call A0's preparatory `siOriginWitnessViolation` (PR #116, §3.8), and does not compare `observed_basis` with the live clock (A7 category 2 is B1).
- It makes no positive catalogue eligibility decision. Only the `catalogue_sha256` shape is checked, with no digest equality and no LC-05 disposition (A12 §3).
- It infers nothing from the spelling of `observed_basis.unit` (A17 §2).
- It performs no authentication, session binding or `transaction_id` derivation, and it is not a model tool-argument contract (OSQ-10; v0.6 §6.1 belongs to the B1 ingress). The GM-facing interaction stays low-friction, and the player never fills in technical IDs.
- It attributes nothing to `trigger.ref`, `cause` or `publication` beyond their strict types (OSQ-2, OSQ-3).
- It declares no Role Registry row and no enrolled-owner or §10 catalogue; those belong to B1 (OSQ-8).
