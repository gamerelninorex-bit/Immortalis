# Host-Requested, Independently Confirmed Active-PC Observation Foundation

One bounded, **mechanism-only**, host-neutral interface by which a compatible, locally configured chat/agent host can **request** a current active-PC LOOK/OBSERVE — and by which that request becomes an observation **only** through the already-established, separate, fresh confirmation on the trusted local operator console and the existing producer. After the independently confirmed observation, the host can receive only the existing earned current Glance through the existing protected read path (`docs/protocol-player-view-mcp-foundation.md`, PR #69).

## The one loop

```text
host (AI chat client)                operator's console (a different process, a different channel)
─────────────────────                ───────────────────────────────────────────────────────────
request_active_pc_observation  ──►   (a non-canonical ASK is left in the owner-only retained state)
   "A request was left. Nothing has
    been observed or decided."
                                     immortalis-observe-request-answer
                                       re-proves the ask against canon, then runs the EXISTING observeSurroundings:
                                       states the exact choice, draws a FRESH nonce, reads the very next line;
                                       only "observe-surroundings <nonce>" typed THEN confirms (subject-bound, one use);
                                       asks the AI referee host the existing F-014D question; the engine derives the verdict;
                                       Epistemic commits the receipt and packet only if OBSERVATION_ESTABLISHED
read_current_observation_glance ──►  (the EXISTING, separately authenticated, read-only player-view server)
   the existing presentation, byte for byte, or the one opaque refusal
```

## The host's request (the host supplies no identity, time, basis, source or authority)

1. **Admission and lifecycle** are exactly the read server's (JSON-RPC 2.0 only; request identities strings or integers; `initialize` then `notifications/initialized` before any tool is listed or called; a closed one-tool surface). A message that fails admission never reaches the trusted request: the package and the retained state are not opened.
2. The tool takes **no arguments**. **Any** argument at all — a "confirmed", a copied "yes", a challenge, a role, a permission, a character, a basis, a verdict — is an over-claim: the call is refused **before the package or the retained state is touched** and nothing the host named is ever carried.
3. The invoking operating-system user must own the campaign package (closed to everyone else) and the owner-only retained-state directory (`verifyLocalOperator`). This identifies **no person and no remote login**.
4. The host must be the one the operator bound _to ask_, holding the secret of that binding. A matching secret **confers no role and no permission and is not authorization to act**: it entitles the host to leave a request for the operator to consider.
5. The campaign opens through the engine's owner-verified re-open under its single-writer lock; a writer already active, an uncommitted journal tail, a stray file, a stale lock (never reclaimed here), an Epistemic integrity violation or an I/O error fails closed; nothing is repaired or altered.
6. The **authorized player view and the canonical active-PC binding must agree** (the same `releaseProblems` / `bindingProblems` proofs the observation command and the read make). The character is the one **canon** proves; the host names none.
7. Only the committed canonical time is read; an unestablished basis is refused. **No scene, observation, decision or packet is consulted to decide anything**, so the request cannot depend on, or reveal, hidden observation state.
8. The one non-canonical ask is left: `{campaign, operator uid, host identity, proved character, canonical basis, random identity}`. It states no choice, confirmation, verdict, world fact or time to advance. A repeated request for the same character at the same basis is the same ask (whoever left it); an ask for another basis or character is stale and is replaced; concurrent requests converge on one file.
9. The host is told only that a request was left, in fixed words: _"Nothing has been observed and nothing has been decided: the player must separately choose and confirm on their own console, and may decline. This request is not that choice."_ Every failure — an unbound host, a wrong, foreign or reused (or read-credential) secret, another campaign or operating-system user, a mismatched character, a writer that is active, an unreconciled package, an unestablished basis and every over-claiming argument — is the same one opaque `OBSERVATION_REQUEST_UNAVAILABLE` refusal, byte for byte and with the same error flag.

## The operator's answer (the player's choice is made here, if at all)

- Run on the operator's own console by the operator: `immortalis-observe-request-answer --campaign <dir> --campaign-id <id> [--operator-dir <dir>] [--referee-wait <s>] [--request-wait <s>] [--reclaim-stale-lock]`. It names no character, role, permission or confirmation; the character is the one the request carries and canon re-proves.
- It re-proves the ask: the file is a valid ask of this campaign and operator; the host is still bound _for that character_; the player view still proves; and the current canonical basis **equals the basis the ask was made at**. A stale or no-longer-bound ask is **discarded** and the operator is asked nothing; a campaign that cannot be proved right now (a writer, an unreconciled package) **keeps** the ask and reports it.
- It then says plainly _"A HOST HAS ASKED THAT YOUR CHARACTER LOOK. That is only a request: it is not your choice, it confirms nothing, and nothing has been observed."_ and runs the existing `observeSurroundings`, which states the exact choice, draws a **fresh** challenge **after** the request exists, and accepts only the verb and challenge typed back on the **very next line**. A recorded or pre-typed "yes", a free-text line, an empty line, end of input or a stale phrase declines. The confirmation is a module-private, subject-bound, one-time token. **This slice never builds, passes or receives one.**
- The existing producer is unchanged: the AI referee host is asked the existing F-014D question built only from committed facts; the engine validates the answer against the delivered text and derives the verdict; only `OBSERVATION_ESTABLISHED` earns the Epistemic receipt and the F-017 event-triggered packet at the **unchanged** canonical basis (no Temporal object, no time advance). A negative or unresolved reading is retained as sealed audit evidence and is immutable; the host is never re-rolled.
- The ask is consumed once the choice is settled (received, not established, declined, or any definite refusal). It is **kept** where the choice was not settled — the referee has not answered or is unavailable, the answer was invalid, the outcome is unknown, or the session could not open — so the operator runs the same command again. A crash after the commit but before the ask is cleared converges on the next answer **without a new choice** (`observeSurroundings`' own one-observation-per-character-per-basis identity).

## Boundaries

1. **Zero canonical mutations by a request.** A request writes no canonical byte: not an intent, an observation, a receipt, a decision record, a packet, a role binding, a target or a Temporal time. The package is byte-identical before and after any number of valid or over-claiming requests; the only file written is the ask in the operator's retained state.
2. **No host or model confirmation.** The ask carries and accepts no confirmation. `observe-request.ts` and its siblings on the host's side cannot import, name or call the confirmation, observation, referee or terminal surfaces (a static check), and `observe-request-answer.ts` only `say`s to the terminal and reaches the choice only through the unchanged `observeSurroundings`.
3. **Transport separation.** `read_current_observation_glance` is neither converted into a command nor given a request authority; the read server lists exactly its one read-only tool and calls to the request tool there are `unknown tool`. The request credential opens nothing on the read surface and the read credential opens nothing on the request surface. The interpreter-only referee surface is byte-identical. `role.player` / `permission.player_choice.commit` are named nowhere in the slice.
4. **One refusal; no hidden-reason leak.** An obstruction, an absent observation, a configuration problem and any other sealed state are indistinguishable to the host on both surfaces: the request acknowledgement is the same whatever the world holds, and the read is the existing opaque refusal. The operator's console, too, says the same for every non-receipt.
5. **No long-lived secret in a prompt or log.** The host's secret travels only as a file _path_ (an owner-only regular file; a symbolic link, another owner's file or one anyone else can touch is refused), is never an argument, an environment value or an output, and the binding keeps only its SHA-256 digest.
6. **Isolation.** Two campaigns with equal-looking identities share no ask, binding, secret or context: the binding, the ask and the retained state are per campaign, and cross-wiring any of them is refused.

## Using it

```text
# the operator, once the character is authored, placed, and canonical time is established (existing commands):
immortalis-operator author-character … ; immortalis-operator establish-character-locus …

# two SEPARATE trusted bind actions (neither names a character, role or permission; each proves the view against canon and writes an owner-only secret file):
immortalis-observe-request-bind --campaign <dir> --campaign-id <id> --host-id <host> [--operator-dir <dir>]    # may ASK
immortalis-player-view-bind     --campaign <dir> --campaign-id <id> --host-id <host> [--operator-dir <dir>]    # may READ (PR #69)

# in the host's MCP configuration (each bind action prints its line; the secrets themselves are never printed):
immortalis-observe-request --campaign <dir> --campaign-id <id> --operator-dir <dir> --host-id <host> --secret-file <path>
immortalis-player-view     --campaign <dir> --campaign-id <id> --operator-dir <dir> --host-id <host> --secret-file <path>

# on the operator's own console, when the host has asked (--request-wait waits for one to arrive):
immortalis-observe-request-answer --campaign <dir> --campaign-id <id> [--request-wait <seconds>]
```

## Not implemented (fail closed, not guessed)

Free-text or conversational intent comprehension of "I look around" (the host's own classification of a look is not a trusted semantic fact; this slice makes the bounded operation host-callable _after_ separate human confirmation and certifies no natural-language parsing); remote human login or any claim that OS-owner verification identifies a person on the Internet; a non-model-controlled confirmation channel other than the operator's console (an anything-able-to-write-to-the-console is-the-operator limit, unchanged); an always-on host or request notification (the operator runs the answer command, optionally waiting for a request); host-visible request status or progress; unrestricted interactive GM operations; natural action duration or consequences; actor decisions; recurring movement; revocation or rotation of a host binding other than the operator removing it from the retained-state directory; any model, provider, network, paid API or credential; a Focus or Depth read. This slice alone does not satisfy First Playable R2–R8; it closes the host-request → separate player-action authorization → committed receipt → lawful same-host read handoff for one ordinary LOOK/OBSERVE only.

Each request and each answer briefly takes and releases the package's single-writer lock (the engine has no read-only open, and none is added). A package whose lock is held by another process reads as the opaque refusal for that moment (the host may simply ask again) or, on the operator's side, as an unavailable-but-kept ask; a request killed mid-flight can leave a lock that only the operator's explicit `--reclaim-stale-lock` takes over.
