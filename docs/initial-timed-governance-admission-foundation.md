# Initial Timed GIP Opening and Earned Sunset Admission Foundation

> **OOC DEVELOPMENT / SCENARIO INSTRUMENTATION.** This is an out-of-character local console path that lets an operator author, confirm and commit **ONE coherent, fully authored GIP chain** — one continuing Institution Identity, its one Office / Authority Locus, that office's one Scope Binding and one initially `active` Governance Instrument carrying one exact future `sunset_condition` — at an already committed canonical time of a fresh, operator-confirmed, **pre-play** scenario, **before any player character is bound**. The records are a **stipulated opening premise**: not an engine judgment of historical legal validity, not a finding that anyone chose, consented to or deliberated anything, not an actor, a mind, a decision body, a membership or a society's adoption, and not an enactment. It creates no world, locus, source, game actor or character, and **advances no time and expires nothing**.

Bounded implementation slice (`@immortalis/operator`: `establish-timed-governance`), composed from the **already implemented** GIP owner operations `GipAdapter.establishInstitution`, `establishOffice`, `establishScopeBinding` and `establishSunsetInstrument`. The last publishes the Instrument together with GIP's own enrollment receipt for its sunset and then has the Temporal owner register exactly the object `gipSunsetTemporalObject` derives; this command writes **no owner fact and no Temporal object of its own**. No `packages/contracts`, `packages/engine`, `packages/protocol` or `packages/testkit` module changed; there is no new GIP operation, owner, facet, schema, key class, lifecycle, enum, receipt format, status gate, scheduler, clock tick or general GIP authoring framework. The shipped binary registers no owner extension.

Authority: the BLUE v5.2-A1 bounded implementation brief "Initial Timed GIP Opening & Earned Sunset" (native pin `2026-10-22T09:16:27.684Z`) on official `main` `418f5a0673c77020e0ddc6aca99cdcf7df6ab353` (after merged #75–#79), under F-027 v1.0 (`spec/f027/spec-lock.json`, blob `43e4325789488e155c60f2deae5028e44286d795`, unchanged) and the frozen WS-007 subset the existing GIP and Temporal code already implements (Institution Identity Reference, Office / Authority Locus with exactly one of `holder_ref` or `decision_body_ref`, Authority Scope Binding, the core Governance Instrument with `validity_by_order[]` independent of lifecycle, and the one optional `sunset_condition` with its `active` → `expired` earned-boundary close). **Only that already-locked, already-implemented subset is used** — no future political, legal, succession or enforcement semantics are adopted. **No source pin, Runtime Contract snapshot, open gate, acceptance row or status changed. F-028/OB-030 remains Blocked, PF-6 inactive, IA/V unpromoted.** Local success is not provider or recovery acceptance. ## The command

```
immortalis-operator establish-timed-governance --campaign <dir> --campaign-id <id> --governance-file <file> [--operator-dir <dir>] [--reclaim-stale-lock]
```

The governance file is one strict JSON document:

```
{ "format": "immortalis-initial-timed-governance", "format_version": 1,
  "publication": { "basis", "secrecy" },
  "canonical_time": { "unit", "value" },
  "institution": { …InstitutionIdentity… },
  "office": { …OfficeAuthorityLocus… },
  "scope_binding": { …ScopeBinding… },
  "instrument": { …GovernanceInstrument… } }
```

Each of the four records is exactly the unchanged owner contract (`packages/contracts/src/gip.ts`, `gip-scope-binding.ts`, `gip-instrument.ts`). Every object is strict, every required field explicit and nothing defaulted: an optional field is omitted when absent (never `null`), an office carries **exactly one** of `holder_ref` or `decision_body_ref`, `validity_by_order[]` is carried exactly as authored (an explicitly authored empty array or a repeated governing order is carried, never reordered, deduplicated or interpreted), and the file can carry no owner, facet, version, receipt, Temporal object, boundary, process, lifecycle result, due flag, clause, renewal rule, successor or predecessor-of-institution field, discriminator or "confirmed" claim (each is an unknown field and is refused). `publication.basis` and `publication.secrecy` are authored and preserved verbatim (F-027 defines no vocabulary for them); they are never defaulted.

**This path admits one bounded family**, as its own eligibility conditions (the GIP owner's admission still judges everything again): the office belongs to the institution and the Scope Binding to the office, by exact canonical identity; the Instrument's `source_authority_ref` is exactly that office's address and its `scope_binding_ref` exactly that binding's address; its `lifecycle_status` is `active`; and it carries a `sunset_condition` that is an instant strictly after `canonical_time`, in the same unit. A sunset-less Instrument, an expired, pending or suspended one, a differently-addressed authority, a date string, a duration and a non-future instant have no representation here. Authored text is a single line: any control character, line break or line/paragraph separator is refused so that nothing authored can rewrite the operator's console.

The file is read once, from one open descriptor: a regular file (not a link) owned by the invoking OS user and writable by nobody else, of bounded size. What was read is what is shown, confirmed and committed; a file changed afterwards cannot change it.

**The records are authored opening premises, not conclusions.** An opaque `holder_ref` or `decision_body_ref` is only a source-defined reference: this command never resolves it, never pretends its referent exists, consented or deliberated, and creates no actor state. The Instrument's `validity_by_order[]` entries are authored and are never derived or reconciled from anything; its `operative_effect`, `authority_basis_ref` and every reference are carried, never dereferenced.

## Sequence

1. **Read and check the file** (above). Nothing is asked of the console if it is refused.
2. **Open the existing package** for the local operator (the usual OS-user verification, the package lock, journal replay and canonical integrity). This command **never creates, adopts, repairs or clears** a package: a missing or foreign directory, or another campaign identity, is `SESSION_UNAVAILABLE`.
3. **Read the established locality from canon** (`establishedLocality`, read-only, shared with the earlier commands): the ORIGINAL world, locus and source that one `establish-locality` setup identity committed, each still the version-1 fact that setup wrote. None held → `LOCALITY_NOT_ESTABLISHED`; held but since advanced → `PRE_PLAY_CLOSED`. (This is this path's own pre-play lane, as the earlier admissions use it: a fresh, operator-confirmed scenario. The GIP records themselves depend on no world fact.)
4. **If every stage of this identity already committed** (a repeat, a lost reply, a restart): judge them on the immutable committed record. Each of the five groups (below) must be exactly the one write set of this proposal, with the exact value, the GIP (or Temporal-kernel) owner and facet, the operator's technical identities, and reads of — and dependencies on — exactly what it was established against. They are verified and reported **without asking again and without a write**. A stage committed with other content, out of order, or whose fact is not held is `GOVERNANCE_CONFLICT`. A record the owner has since advanced beyond version 1 (the sunset has been reached and GIP's stage has expired the Instrument) is `PRE_PLAY_CLOSED`, never "established". Replay is pre-play only: once a player character is bound, an identical rerun is `PRE_PLAY_CLOSED` with no prompt and no write.
5. **Pre-play and consistency refusals**, all before the console is asked and with no write: a bound player character → `PRE_PLAY_CLOSED`; **any other GIP fact already held in the campaign**, or anything already held at one of this proposal's keys, the receipt slot or this Instrument's Temporal object, → `GOVERNANCE_CONFLICT`. The first is this path's own fail-closed condition (one initial opening per campaign by this path, which also keeps the single enrollment-receipt slot free), not a GIP rule.
6. **Require the existing canonical time** (until the Instrument and its receipt have pinned it). The opening is established **at** a canonical time, and this command creates, chooses and advances none. The Temporal owner's committed state must exist and be valid (`TIME_NOT_ESTABLISHED` otherwise — a missing prerequisite, never a success), and the authored `canonical_time` must equal it exactly, in the same unit (`TIME_MISMATCH` otherwise, including a stale time). A resumed Temporal registration is judged on GIP's already committed receipt alone. The shipped operator tooling has no path that establishes canonical time; the disposable tests establish it through the Temporal owner's own operation as a scenario premise, and a real scenario needs its own lawful time origin, which this slice does not provide.
7. **Prove the owner path admits and registers it**: on a throwaway package that is then removed, the campaign's canonical time is established through the Temporal owner's own ordinary route and the four records are run through the genuine GIP owner operations; the sunset must read back as registered. A refusal is `INVALID_GOVERNANCE` with nothing written to the campaign. The scratch package is never reused and is never given a tick or an advance.
8. **Confirm, once.** The whole proposal is shown (authored text JSON-quoted; identifiers carry no control character) with what it does **not** do and the stages still to commit. The operator types `establish-timed-governance <fresh challenge>` on the very next line; anything else, a stale or pre-typed line, another verb's phrase or end of input declines and nothing has been written. The confirmation is a one-time token bound to the verb and the exact subject (campaign, established locality, governance identity, pending stages and the whole document).
9. **Commit in dependency order**, each a separate durable publication (`PROGRESS <stage> COMMITTED …`): the Institution Identity through `GipAdapter.establishInstitution`; the office through `establishOffice` (reading and depending on the institution's committed group); the Scope Binding through `establishScopeBinding` (on the office); and the Instrument through `establishSunsetInstrument`, which in one create-only group commits the Instrument **and GIP's enrollment receipt** (`sunset_at` copied from `sunset_condition`, `basis_time` the canonical time of commit) and then has the Temporal owner register exactly the derived object under identities derived from the Instrument alone (`PROGRESS sunset registration COMMITTED …`). The operator never writes through any raw `store.commit`, never writes a receipt, a Temporal object, a boundary index entry, a lifecycle or a time, and never engages a reconciliation.
10. **Verify on a fresh reopen.** The package is closed and reopened through the engine's owner-verified open; each record is read back through the GIP owner's own typed reads and compared with the confirmed document; its key, owner/facet, version 1, provenance and committed group are compared; GIP's receipt is compared with the independently written-out expected receipt; the Temporal object is compared with the object derived from the confirmed Instrument and the authored canonical time and must be present in the boundary index exactly once; **every fact the campaign held before is compared with its pre-commit self** (the canonical time included; the boundary index may only have gained this Instrument's one entry), and the fact count and revision are exactly the expected number greater (five commits for a full run). Only then is `GOVERNANCE_READY` reported.

Statuses: `GOVERNANCE_READY`, `GOVERNANCE_INCOMPLETE`, `GOVERNANCE_OUTCOME_UNKNOWN`, `GOVERNANCE_REFUSED`, `GOVERNANCE_VERIFICATION_FAILED`, `LOCALITY_NOT_ESTABLISHED`, `PRE_PLAY_CLOSED`, `TIME_NOT_ESTABLISHED`, `TIME_MISMATCH`, `GOVERNANCE_CONFLICT`, `SESSION_UNAVAILABLE`, `DECLINED`, `INVALID_GOVERNANCE`, `GOVERNANCE_FILE_UNTRUSTED`, `GOVERNANCE_FILE_UNREADABLE`. `GOVERNANCE_READY` means exactly: every record, GIP's receipt and the Temporal registration are committed under this identity, verify, and nothing earlier changed. A partly committed chain is `GOVERNANCE_INCOMPLETE` (a known refusal) or `GOVERNANCE_OUTCOME_UNKNOWN` — **never** a success — until the same command is rerun to finish it.

## Identity, convergence and fail-closed

The service authors only the technical publication identities and derives them from the exact authored content, never from a clock or a random value: `<id>` is a hash of the campaign identity and the whole document, giving for each stage `<name>` ∈ {`institution`, `office`, `scope_binding`, `instrument`} group `operator-initial-timed-governance:<id>:<name>`, intent `operator-initial-timed-governance-intent:<id>:<name>` and cause `operator-initial-timed-governance-cause:<id>`. The Temporal registration's group and intent are the ones the GIP owner derives from the Instrument alone.

- **The same confirmed proposal always reaches the same identities.** A retry after a crash or a lost reply replays what committed (RC-16, by the store's own identity check) and finishes what did not, **resuming only the exact original durable request** — an Instrument committed without its registration is finished by presenting its original intent again, which GIP replays by identity before the Temporal owner registers the sunset exactly once; it never writes a second, rerolled, reordered or altered record, Instrument, enrollment, Temporal object or stage.
- **Any different content under the same identifiers meets the committed key and is refused**; committed facts are never replaced. A different proposal offered while the chain waits is refused, never substituted; a record another writer committed under a waiting key is a conflict, neither adopted nor replaced.
- **No retained state is added.** There is no new pin, receipt or ledger format: the committed record in the package is the only memory of what committed (the session still opens the existing owner-only retained-intent directory, unchanged).
- **Until the sunset is registered it cannot be passed.** While the Instrument and its receipt are committed but the Temporal owner has not yet registered the boundary, the existing kernel rule refuses (`ENROLLMENT_PENDING`) any advance that would reach or pass the sunset; rerunning this command finishes the registration.
- **Once pre-play ends, setup is closed**, replay included: a bound player character, an advanced locality fact, or a record the GIP owner has since advanced, all refuse.

## Recovery

The package's own file lock and durable-write order are used unchanged. A kill leaves the lock; it is refused until the operator explicitly passes `--reclaim-stale-lock`, which the engine honours only for a provably dead holder. Tests interrupt before each of the five commits and after each (a dropped write and a lost acknowledgement at every cut, including after GIP's Instrument and receipt but before the Temporal registration), by a known refusal of each stage, by a failed reopen after the close, by a real `SIGKILL` of the shipped binary at the console, after each of the first three records and after the Temporal registration, and by a failure before **and** after every mutating filesystem operation of the whole command; each converges on the uninterrupted campaign (equal head, state and journal hashes), with no record present without its prerequisite, no registration without its Instrument and no duplicated Instrument, object or stage. Independent corruption mutations of the committed groups (an altered value, version, basis, secrecy, owner, cause, read, dependency, receipt, boundary or index entry, an extra write, an out-of-order group, a fact no longer held) are refused and never adopted.

## The disposable witness (tests only)

`tests/integration/initial-timed-governance-foundation.test.ts` then exercises the **existing** Temporal route on a disposable campaign, with the genuine `gipSunsetExpiryProvider`, through a separate scripted exact-target progression choice (`player-ooc-advance-choice`). One tick short of the sunset, nothing resolves and the Instrument is exactly as committed; at the sunset (the comparison is inclusive) the registered boundary resolves GIP's one stage and **GIP alone** changes `lifecycle_status` from `active` to `expired`, one version on, changing nothing else — not `operative_effect`, not `validity_by_order[]` (validity is order-relative and independent of lifecycle), not the authority premises. The tests assert the independently derived value (the authored document with that one transition), never a fixture that supplies `expired`; the smallest falsification (the same opening, a boundary reached versus not reached, and a later sunset that the same advance does not reach) shows the outcome follows the registered term and canonical time. The later advance is a test exercise of existing owner code, **not a new command or an automatic part of this admission**.

**This is a mechanism-only independent-world causal witness. It does not prove natural human play, interpretation, legal enforceability or validity, actor cognition, individual receipt, societal adoption, world-state perception, ordinary player-directed time or first-playable closure.** The ordinary client/host player-facing effect, actor reception and understanding, independent NPC mandates and natural travel and wider continuation remain an **EXTERNAL PREREQUISITE MISSING** and are not claimed.

## Security

The full proposal (identifiers and every authored text) is shown only on the operator's own console and held only in the owner-verified package. It is not written to the retained-state directory, and no host-facing surface (referee, player-view, observe-request or advance-request MCP servers, the protocol package) imports or names this command. **No MCP, phone or client GIP list, search or creation tool is added.** No model, MCP client or command-line flag can attest the human confirmation, and no authored content is interpreted by a language model. The module has no network, child-process, environment or global-state access. Outside its scratch dry run it uses no Temporal coordinator, registers no object, establishes no time and advances nothing.
