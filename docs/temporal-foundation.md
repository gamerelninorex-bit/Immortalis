# Turnless Temporal & Resolution Transaction Foundation

Third bounded slice, built on the Campaign Continuity Foundation (`docs/campaign-package.md`) and the Canonical World Identity & Owner Foundation (`docs/canonical-world-foundation.md`). The canonical campaign can now **advance from one canonical temporal basis toward a bounded target, resolve only the causally engaged dependency cone, stop with a lawful remainder, and — after save, close and load — continue without temporal, transaction, dependency, stage or provenance drift.**

Governing lock: `spec/f027/spec-lock.json` (F-027 v1.0). Sources: F-014B Temporal Resolution Kernel v2 §§2–4, 6, 7, 9, 13, 17 (lock pin `2026-09-25T23:42:29.547Z`) and F-017 Whole-Engine Dependency Graph v0.3 §§2–4, 9 (derived ordering only). No provider, host protocol, migration, population, economy, actor, health, epistemic, recurrence or scheduler exists, and every F-027 open gate is unchanged — in particular **CAL-01 (APPROXIMATE-PARTITION tolerances) remains UNCALIBRATED and is not used**: the proof is `EXACT-PARTITION`.

This is a **foundation proof**, not a gameplay feature. All fixture data is synthetic (`packages/testkit/src/temporal-fixtures.ts`); T0/Tb/T1 are test coordinates.

## One canon: how it reuses IM-11 / IM-12 / IM-17

Nothing new is persisted outside the existing campaign package. The kernel's shared state (F-014B §2) is ordinary `OwnerFact`s written through `store.commit`, so the existing validation, expected-version checks, RC-16 receipts, idempotent replay, unknown-outcome reconciliation, hash-chained journal and package/load integrity are the ones in force. **The package format is unchanged (still format version 1); there is no second journal, save, sidecar or recovery identity.**

The kernel owner is `temporal_kernel` / `temporal_coordination` (IM-02, F-014B §2), registered in the IM-03 registry beside the world/PC owners. It owns orchestration only — never a substantive world fact — and its key spaces are exclusive:

| Fact                   | Key                         | Lifecycle | Holds                                                                                                        |
| ---------------------- | --------------------------- | --------- | ------------------------------------------------------------------------------------------------------------ |
| Temporal state         | `temporal/state`            | advancing | canonical time; last transaction; the stop/remainder continuation (target still owed, unresolved dependents) |
| Active boundary index  | `temporal/boundary-index`   | advancing | only the active earned boundaries (never recurrence history); sorted `(time, object)`                        |
| Temporal object        | `temporal/object/{id}`      | advancing | the RC-10 surface                                                                                            |
| Resolution transaction | `temporal/transaction/{id}` | sealed    | the RC-05 record: one per outer resolution, immutable once committed                                         |

**Kernel admission (IM-11).** (1) Canonical time never moves by itself: after the explicit establishment, `temporal/state` changes only in the same group as exactly one sealed transaction whose actual stop _is_ the new time, whose opening basis is the state it read, and which never moves time backward — there is no tick, no turn and no other path. (2) A transaction touches exactly the objects it engaged, each across the boundary it had earned, changes no declaration, and the index loses exactly those entries — an unrelated (dormant) object cannot be rewritten. (3) The index and the objects agree in both directions, in the state's unit. (4) A transaction commits only after the stage groups it cites (they are group dependencies). (5) The continuation is exactly the transaction's outcome. (6) **Canonical time cannot pass active material work**: after a transaction, no active boundary lies strictly before its stop; at the stop instant none may remain unless the stop is `DEPENDENCY_UNRESOLVED` and the entry belongs to an engaged, still-active object; `CONDITION_SATISFIED` is proved by the exact requested `STOP_AFTER_BOUNDARY` object/boundary having been crossed and retired by that transaction, stopping at its instant. (7) **A held continuation is consumed or it stays**: while the state holds a continuation, the next transaction must declare `continues` = that transaction **and carry its unfinished request forward** — if the sealed prior transaction stopped with unresolved dependents, the same requested target and condition (canonical equality); if it left only a target remainder (its condition already resolved), exactly that target; there is no cancellation or supersession, so unrelated progress cannot bypass it — for the coordinator and for a raw kernel commit alike. The same invariants are re-verified on every load.

**Stage and transaction publication.** Each stage is published as its _owner's_ commit group (through an IM-03 adapter seam, `StageProvider`); the coordinator then publishes one kernel group with the transaction, new state, engaged-object updates and index change atomically. All identities are derived only from the StageKey or the caller's transaction id (`temporal/identity.ts`), so retry, replay, crash-and-reopen and repartition reach the existing receipt. A stage that an earlier attempt already committed is **adopted from the journal** (`CampaignStore.committedGroup`, an IM-12 cold-history lookup) — never recomputed under a newer source version, never recreated as a sibling.

## The advance, in order (F-014B §6, F-017 §4)

1. Read the canonical state; validate target (not before the basis, same unit) and any `continues` link against the persisted remainder.
2. Query the **active boundary index** for earned boundaries due by the target. No whole-world scan; an object is read only if the index says its boundary is due. Unrelated dormant state is not read, resolved, invalidated, staged or committed.
3. For each due instant, in causal time order: import the engaged objects' declared stages with their exact NOW/CLOSE reads; build the transient graph; classify every read (CLOSE must name a close the _producer_ declares, and the producer must be among the engaged stages); test instantaneous cycles on NOW edges only over stage identity; resolve in dependency order; independent work stays independent.
4. Stage each stage transiently, let an observer see it (`afterStaged`), recompute **in place under the same StageKey** if an unresolved source/invalidator changed before commit, then publish it through IM-11.
5. Stop at the declared condition, at the first unresolved component, or at the target; carry exactly (lazily) to the target when nothing earned remains.
6. Commit the transaction, new canonical time, continuation, engaged objects and index in one kernel group.

## Fail-closed cases

An unresolved stage is _not credited_, its dependents wait, independent stages proceed, and the transaction records `DEPENDENCY_UNRESOLVED` with the reason: `INSTANTANEOUS_CYCLE` (no GROUP is authorized, so every NOW cycle is unlawful and nothing — partition, slice, horizon, version, invented phase or owner — breaks it), `UNSATISFIABLE_ORDER`, `CLOSE_BASIS_UNDECLARED` (a slice/horizon token cannot stand in for the producer's named close), `PREDECESSOR_ABSENT`, `SOURCE_ABSENT`, `SOURCE_OWNER_MISMATCH`, `PROVIDER_ABSENT`, `CLOSE_SOURCE_ADVANCED` (the close's source moved past the close), `VALIDATION_REJECTED` (IM-11 refused the staged group), `PREDECESSOR_BLOCKED`. An unresolved transaction still records every engaged object in RC-05 evidence: a still-active object is represented (`boundary: STILL_ACTIVE`, no `version_after`) but is **not mutated or retired**; only `RETIRED` objects are written. A request made while a continuation is held, without consuming it, fails `CONTINUATION_HELD`. Re-presenting a committed transaction id with a different publication `basis` or `secrecy` is `TRANSACTION_CONFLICT`, compared against the committed fact and journaled group. An unknown durable outcome is returned as `UNKNOWN_OUTCOME`, the store stays poisoned, and recovery is **reopen, then re-present the same request by identity** — never a blind retry.

## Judgment calls and open residuals (none resolves an open gate)

- **Time representation.** F-027 fixes no calendar, unit or granularity. Canonical time is an opaque exact coordinate `{unit, value}` (non-negative integer). No tick, no calendar and no calibration is implied; coordinates in different units are not comparable and fail closed.
- **Origin of canonical time.** `establishCanonicalTime` is an explicit authored publication. How a real campaign originates its time belongs to a later slice.
- **One facet for the kernel.** A commit group is per owner/facet; the kernel's four kinds share one facet so a transaction, state, index and object update commit atomically under one F-014B rule citation.
- **Where stage declarations live.** A stage's identity, reads, produced keys and close are declared in the governed object's `dependencies` (RC-10 "dependency declarations"), so the dependency cone is found from the engaged object alone, with no reverse index and no scan. Consequence: **cross-object dependents are not supported** (they would need a consumer registry); one earned boundary per object, resolving all of its declared stages.
- **CLOSE scope.** A CLOSE read must resolve to a producer close among the engaged stages. A read of a _prior-interval_ close already committed is not supported (`PREDECESSOR_ABSENT`). A CLOSE read whose source fact has since moved past the close fails closed (`CLOSE_SOURCE_ADVANCED`): no historical-version reads exist.
- **Stop predicate vocabulary.** One declared predicate, `STOP_AFTER_BOUNDARY` (F-014B W3-CP3 overlay: stops only on declared transaction predicates). Its literal name is ours. No PC-actionable-knowledge interruption (F-014B §10) is implemented; the object states it creates no epistemic interruption.
- **Transaction role context.** Only the already-approved player-choice pair is accepted; the kernel commits by the archivist path (`role.archivist` + `permission.canon.write`). No authority is minted; OB-016 code-era conformance remains open.
- **Consuming a blocked-only continuation.** A continuation can hold only blocked work (a condition-only request that stopped unresolved has no target to owe). It is consumed by an explicit request with `continues` set to that transaction and the **original requested condition** (and target) unchanged; since its boundary is due at the canonical time the retry reaches it. Changing or dropping the held condition, or substituting unrelated progress, is refused. `continueRemainder` remains the helper for a held target only, and for unresolved work it re-issues the original request.
- **Blocked transactions.** Time advances to the boundary reached; the object's boundary is not retired while one of its stages is unresolved, so it stays due and a later transaction adopts the committed stages and retries the rest.
- **Adapter seam.** `StageProvider` is the IM-03 seam; the only implementations are the testkit's SYNTHETIC ones, registered through `StageOwnerExtension`, which cannot reuse or write canonical/kernel key spaces and grants no role or permission. `afterStaged` is an inspection seam used by tests to change a source mid-stage.
- **IM-17 interface addition.** `CampaignStore.committedGroup(intentId)` (read-only). The commit core now retains each committed group beside its receipt, so memory is proportional to journal size — the same order as the existing replay.
- **Two existing assertions changed.** `tests/unit/owner-admission.test.ts` and `tests/conformance/world-foundation-conformance.test.ts` pinned the owner registry to "exactly the three world/PC owners"; they now also list the IM-02 kernel and keep the "nothing else" guard.
- **Cost.** The advance path reads the state, the active index and only the engaged objects and their sources. `verifyTemporalIntegrity` (like `verifyCanonicalIntegrity`) lists all facts once per open — a diagnostic path (CAL-06), not the advance path.

## Deliberately not implemented (fail closed, not guessed)

APPROXIMATE-PARTITION and any tolerance (CAL-01); GROUP mechanisms; SEALED/EVENT/CONDITIONAL edges; recurrence and pre-generated boundary history; more than one earned boundary per object; cross-object dependents; stochastic opportunities/hazards and partition-invariant RNG provenance; mortality coverage; compression/re-expansion; same-time contention beyond bookkeeping order; the information/interruption gate and Actionable Knowledge Time; no-active-PC stop predicates beyond the one declared boundary predicate; any real subsystem's temporal declaration; OB-015 live continuation; any host/MCP/projection/NPK layer, provider, production schema, deployment, migration or PF-6/F-028 step.
