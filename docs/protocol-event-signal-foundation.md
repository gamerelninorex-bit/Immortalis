# Trusted-Context Active-PC Event-Signal Protocol Read Foundation

Thirty-seventh bounded slice, built on the I-001 Event-Signal Projection (`docs/i001-event-signal-projection-foundation.md`, PR #37) and NPK Event-Signal Presentation (`docs/npk-event-signal-presentation-foundation.md`, PR #38) foundations. **A qualified host can now invoke exactly one allowlisted, read-only Resurreccion Protocol operation that names one Event-Signal event and returns only the lawful current active-PC IM-14 presentation produced by the existing IM-13 → IM-14 path for the campaign its trusted context is bound to.**

Governing lock: `spec/f027/spec-lock.json` (F-027 v1.0 composed with F-027-CD1 v1.0). No source pin, Runtime Contract snapshot, open gate or acceptance status changed. The IM-13 and IM-14 modules and contracts are byte-identical to PR #37 / #38 (asserted by hash). PF-6/F-028 remains BLOCKED / NOT ACTIVATED.

## The trust boundary

1. **Authority is the context, never the request.** The campaign (its read-only committed-fact view) and the recipient come from the trusted context the service established by its own means. Authentication, credentials, tokens, sessions, accounts and tenants are **not modelled, not implemented and not claimed**; the context is an internal prerequisite.
2. **An unforgeable handle.** A context is only a value returned by the binder. A fabricated, parsed (`JSON`), spread or prototype-copied object is not in the registry and is refused.
3. **The recipient is not trusted for canon.** IM-13 still validates the context's recipient against the campaign's canonical active-PC binding on every read, so a wrongly bound recipient yields the refusal.
4. **Strict, allowlisted request.** Extra fields (campaign selectors, recipient substitution, role/permission claims, paths, source identifiers), any other operation name (including internal ones such as `getFact` or `listFacts`) and a malformed event id are refused **before any state is read**.
5. **One refusal.** Every failure — over-claiming request, forged context, throwing view, unavailable, stale, historical, inaccessible or non-current event — is the existing IM-13 refusal (`PROJECTION_UNAVAILABLE` / `"no projection is available"`, no details). No cause, validator detail, hidden-state existence or identity is distinguishable.
6. **Causally inert.** The only capability reachable is IM-13's read-by-identity view. Nothing is written, committed, retried, scheduled, drawn, advanced or cached; the context holds the view, never data, so each call re-derives and a later arrival is seen at once.
7. **Isolation.** Two contexts bound to two campaigns with identical event and PC identifiers each read only their own campaign. This is bounded campaign-isolation evidence for this operation, **not** a claim that authentication/session isolation is complete.

## Not implemented (fail closed, not guessed)

Login, credentials, token/session/account/tenant lifecycle; MCP, HTTP, REST or WebSocket transport; deployment or provider adoption; a generic protocol framework; general context retrieval or campaign dumps; natural-language or RC-15 action routing; confirmation/commit surfaces and mutation operations; save/load/resume operations; Glance/Focus/Depth; Player Referential Authority; memory/retrieval; broadcast/cohort access; general NPK scene generation; migration; production schema; licensing; PF-6/F-028.
