## 4. RF-22 and a RED erratum (both about changed task questions)

**RED erratum to S5-CT-2 (RED's own text).** The Stage 5 record said that an operation whose context was changed by a repair "cannot republish under its old identity (`referee-exchange.ts` 771 returns `TASK_CONFLICT`)". That conflated two cases. Task identity is derived from the exact context (`collection-referee.ts` 33 to 39; `derive.ts` 263 to 264), so **a changed context produces a new identity, not a conflict**: the old task and answer are orphaned and unreachable by the new question. `TASK_CONFLICT` arises only when the _same_ identity meets a _different document_ (`referee-exchange.ts` 764 to 771 compares the operation and the whole document, rebuilt with the stored nonce). BLUE's UG-2-TASK ("create a separately identified successor evaluation linked to the original operation, repair plan, changed context and displaced task") states the real obligation, the successor relation, more exactly than RED did, and RED adopts that formulation. What stands from S5-CT-2 is unchanged: the write half holds, the read half is unspecified, and a held repair needs a defined way to ask a changed question.

**RF-22 — the same-context, changed-document case (non-gating, precision).**

- **Source basis.** The fixed text of a task document is part of what is compared: the collection task documents embed an `authority_basis` with a pinned `native_pin` and a fixed `purpose` text (`collection-referee.ts` 85 to 92 and 117 to 125). Context is unchanged, so the identity is unchanged; the document differs, so the republished task meets `TASK_CONFLICT`.
- **Issue.** Prospective source adoption, which C, D and MX all require (U3-04), changes those pins and texts. Any task published before the adoption and still outstanding, or answered and not yet consumed, then conflicts on retry, with the context unchanged. The UG-2-TASK rule is written around a changed context ("changed-context task rule") and does not say that the successor relation must also cover a changed document at equal context.
- **Requested delta (one clause).** Extend UG-2-TASK to say that the successor-task relation applies equally when only the task document (authority basis or text) changes at an unchanged context, and that adoption must account for tasks outstanding at the transition. No rule is adopted by this; it is a scope statement for an UNKNOWN.
