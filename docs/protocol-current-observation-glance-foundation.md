## The path (no event identity from the caller)

1. The host sends only the operation name. The trusted context supplies the committed-fact view and the addressed active-PC recipient.
2. The Temporal owner's committed canonical state is read **by identity**; its canonical time is the current basis. Nothing is supplied, moved or written.
3. The event identity is **derived**, server-side, by the existing `observationEventId(recipient, canonical time)` — the observation's own source-qualified identity (one character, at most one observation event per canonical instant).
4. The committed event at that identity must be **exactly the observation-earned event its retained direct-perception decision determines**: `isObservationEarnedFact` plus the Epistemic owner's own `observationEventViolation(..., "VERIFICATION")` over the event's journaled committing group. A coincidentally named, edited, broadcast or ordinary active-PC event is not an observation and is refused.
5. That event goes through the **unchanged** IM-13 `deriveEventSignalProjection`, which still revalidates the recipient against the canonical active-PC binding, the actor-safe packet, the exact current arrival under the latest SEALED resolution transaction and its formation, on every call.
6. The **unchanged** IM-14 `presentEventSignal` presents exactly that projection; the success value is the presenter's value unchanged (contact, optional presented attribution, referent, content). No UI field for a true source, source id, world/locus key, hidden-state marker, capability, interpretation, recognition, knowledge time, intent authorization or "available" flag is added.

## Boundaries

1. **Identity, basis and recipient are trusted-side or derived; never host input.** An over-claiming request is refused, never carried.
2. **Trusted context is not canon.** The recipient is revalidated on every call (wrong client → refusal).
3. **One refusal.** Absent PC/binding/custody, no actual observation, an obstructed one (which earned nothing), an unsealed event, a stale packet after a newer sealed transaction or a moved basis, a forged handle, a malformed request, a throwing view — all are the existing `PROJECTION_UNAVAILABLE` refusal, byte-identical, with no cause, validator detail, source identity or sealed provenance.
4. **Seal and order.** Nothing is readable before decision → owned event → owner packet and provenance → sealed authoritative transaction.
5. **No write, no time.** Nothing is written, committed, cached, retained, retried, scheduled or advanced; canonical time does not move; nothing is marked "seen". Repeated reads at the same lawfully current basis are stable; save/reopen reproduces only what the current source permits; after supersession the earlier packet is not revived (storage is no recall basis, I-001 §11).
6. **No discovery.** One identity is derived and read by key and group identity; no enumeration, scan, search or selection among events, packets, stages or history.
7. **Isolation.** A context bound to one campaign's view cannot reach another's. Bounded evidence for this operation, not an authentication or session isolation claim.
