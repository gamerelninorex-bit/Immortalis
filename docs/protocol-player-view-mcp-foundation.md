# Local Player-View MCP Transport Foundation

One bounded, read-only, **mechanism-only** transport: a locally authenticated, client-neutral **stdio MCP** server that lets a compatible, locally configured chat/agent host request — and receive — only the already-earned **current** Active-PC Glance presentation of the existing `readCurrentObservationGlance` gateway (`docs/protocol-current-observation-glance-foundation.md`, PR #68), or that gateway's one opaque refusal. Built on the active-PC direct observation (`docs/active-pc-direct-observation-foundation.md`, PR #67), IM-13 (`docs/i001-event-signal-projection-foundation.md`) and IM-14 (`docs/npk-event-signal-presentation-foundation.md`).

## What exists

| Piece            | Where                                           | What it is                                                                                                                                                                                                                                                                              |
| ---------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Transport**    | `operator/src/player-view-mcp.ts`               | A standard MCP server over stdio (newline-delimited JSON-RPC 2.0) with **one** tool, `read_current_observation_glance`, which takes **no arguments**. It never opens the package; it hands the host's untrusted arguments to a trusted read and frames what comes back.                 |
| **Trusted read** | `operator/src/player-view.ts`                   | On every call: verifies the local OS owner, authorizes the host, opens the campaign through the engine's owner-verified re-open, proves the one authorized player view against canon, then runs `bindTrustedCurrentPlayerContext` → `readCurrentObservationGlance`, both **unchanged**. |
| **Host binding** | `operator/src/player-view-exchange.ts`          | The operator-written, owner-only binding of a concrete host identity to a secret (digest only in the file) and to the one character the operator kept and placed. A separate directory, format and secret space from the referee exchange.                                              |
| **Entry points** | `player-view-bin.ts`, `player-view-bind-bin.ts` | `immortalis-player-view` (started by the host) and `immortalis-player-view-bind` (the trusted operator action). Neither is reachable from a host request.                                                                                                                               |

The existing strict protocol request `{ operation: "read_current_observation_glance" }` is **not** enlarged. The tool's name is MCP-level naming only; the host supplies nothing the trusted side could use.

## The path (the host supplies no identity, time, basis, source or authority)

1. The host calls the one tool with no arguments. **Any** argument at all is an over-claim: it is handed to the unchanged gateway marked as such, so the gateway refuses it on the very same read path as a valid request, and nothing the host named is ever carried.
2. The invoking operating-system user must own the campaign package (closed to everyone else) and the owner-only retained-state directory (`verifyLocalOperator`, the boundary the package already rests on). This identifies **no person and no remote login**.
3. The host must be the one the operator bound to this campaign, holding the secret of that binding. A matching secret **confers no role and no permission**: nothing is inferred from a credential, a host name or a model name. The referee exchange's secrets open nothing here, and these open nothing there.
4. The campaign opens through the engine's owner-verified re-open (journal replay, canonical integrity) under its single-writer lock. A writer already active, an uncommitted journal tail, a stray file, a stale lock (never reclaimed here), an Epistemic integrity violation or an I/O error fails closed; nothing is repaired or altered to force a read.
5. **The authorized player view and the canonical active-PC binding must agree.** The character the host was bound to, the character the operator's retained keep names and the character the Role Registry binding makes the active PC are one character, and the release and binding are exactly the ones the shipped authoring command published for that keep (the same `releaseProblems` / `bindingProblems` proofs the observation command makes). Where that cannot be proved, the read is refused.
6. `bindTrustedCurrentPlayerContext({ view, recipient_id })` is built from the current canon with the **proved** character; `readCurrentObservationGlance(context, { operation: "read_current_observation_glance" })` returns the existing `EventSignalPresentation` or its opaque `PROJECTION_UNAVAILABLE` refusal. The MCP result text is that `Result` serialized exactly as the direct read serializes it; a refusal additionally carries the MCP error flag.

## Boundaries

1. **One refusal.** An unbound host, a wrong, foreign or reused secret, another campaign or operating-system user, a mismatched character, a writer that is active, an unreconciled package, an over-claiming argument and every hidden observation state (none, obstructed, committed-but-unsealed, historical, superseded, tampered) are the existing `PROJECTION_UNAVAILABLE` refusal, byte for byte, with the same flag. No cause, validator detail, existence, identity or path is host-visible. A call to any other tool name is a protocol error naming nothing.
2. **RC-14 preserved.** The gateway and the IM-13 guard keep their fixed read shape; the trusted-side proof reads only the character, binding, release and retained keep — never an observation, packet, event, decision or time identity — so it cannot select a path by hidden observation state. Tests compare the ordered reads of a valid call and of every over-claiming call.
3. **No write, no time.** The campaign is open only for the length of one read; the open takes and releases the package lock and writes no canon. Nothing is written to the package, the journal, the intent ledger, the binding or the retained state; no owner fact, role binding, target or Temporal time changes. Repeated reads at the same lawfully current basis are stable; after a time advance or a newer sealed transaction the earlier packet is not revived.
4. **No long-lived secret in a prompt or log.** The host's secret travels only as a file _path_ (an owner-only regular file; a symbolic link, another owner's file or one anyone else can touch is refused), is never an argument, an environment value or an output, and the binding keeps only its SHA-256 digest.
5. **Isolation.** Two campaigns with equal-looking character and world identities share no context or data: the binding, the retained state and the package are all per campaign, and cross-wiring any of them is refused.
6. **Distinct authority surface.** The interpreter-only referee MCP (`referee-mcp.ts`, `referee-exchange.ts`) is byte-identical to the base and gained no player read; `role.gm` is never granted player-viewing authority.

## Using it

```text
# the operator, once the character is authored, placed and has observed (the commands below are the existing ones):
immortalis-operator observe-surroundings --campaign <dir> --campaign-id <id> --player-character <id>

# trusted bind action (names no character, role or permission; proves the view against canon, writes the owner-only secret file):
immortalis-player-view-bind --campaign <dir> --campaign-id <id> --host-id <host> [--operator-dir <dir>]

# in the host's MCP configuration (the bind action prints this line; the secret itself is never printed):
immortalis-player-view --campaign <dir> --campaign-id <id> --operator-dir <dir> --host-id <host> --secret-file <path>
```

## Not implemented (fail closed, not guessed)

A player-owned look/observe intent from ordinary conversation; interactive confirmation; natural action duration or consequences; actor decisions; recurring movement; general client or session identity; remote login or any claim that OS-owner verification identifies a person on the Internet; an always-on host; a remote or HTTP transport; revocation or rotation of a host binding other than the operator removing it from the retained-state directory; any model, provider, network, paid API or credential; a Focus or Depth read. This bridge alone does not satisfy First Playable R2–R8; it closes the present observation-to-compatible-host read gap only.

Each read briefly takes and releases the package's single-writer lock (the engine has no read-only open, and none is added). A package whose lock is held by another process (an operator command is running) therefore reads as the opaque refusal for that moment and the host may simply ask again; conversely a host calling in a tight loop can make an operator command's open report the package as open elsewhere, which the operator retries. A read killed mid-flight can leave a lock that only the operator's explicit `--reclaim-stale-lock` takes over: the transport never reclaims one.
