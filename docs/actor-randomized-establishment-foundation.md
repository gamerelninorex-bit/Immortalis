# Named-Actor Randomized Capability Establishment (WS-016 × F-027-CD1)

Twenty-seventh bounded slice, built on the Named-Actor Character Capability foundation (`docs/actor-capability-foundation.md`) and the Causal Draw foundation (`docs/causal-draw-foundation.md`). The currently fail-closed WS-016 §16 steps 3–4 branch — **genuine uncertainty remains after the smallest established causes** — is now enabled as a **consumer** of the neutral Causal Draw. The Named-Actor owner decides that uncertainty exists, defines the branch-invariant bounded prior (the lawful possibilities and their relative causal weights), reads the meaning of the selected opaque candidate, and commits **its own** basis. Causal Draw stays neutral sampling/provenance infrastructure: it learns no candidate meaning and writes no Named-Actor value.

Governing authority: **F-027 v1.0 composed with F-027-CD1 v1.0** (exact cleared pin `2026-10-02T15:11:03.450Z`, §17 CD-CC-01), **WS-016** Character Capability (Integration Map lock pin `2026-09-24T17:38:59.210Z`, Working Operational Draft pin `2026-09-25T00:18:34.584Z`, §§3, 4, 6, 7, 16, 17, 27.1, 28, 32), and **WS-006 / F-014A v3.3** (pin `2026-09-25T00:18:36.828Z`). The standing literal source-fidelity check was performed before any executable surface changed: the live Notion `page_last_edited_at` of all four pages equals the pinned value, and the text relied on (CD1 §§3–4, 8, 10, 12–14, 17; WS-016 §§16–17, 27.1) was re-read. **No source pin, Runtime Contract snapshot, open gate, acceptance-register row or `spec-lock.json` byte changed.**

## The operation, in order

`establishRandomizedCapabilityBasis({ …publication, capability, resolution })`, where `capability` is the owner's **authored input** — the establishment's actor, capability, materiality, the pinned causes, and `prior: [{ marker, weight }]` (relative positive integer weights, owner-authored; there is no default, formula or table) — and `resolution` is the resolver context CDE-01 requires (the owner assigns itself no authority):

1. **Pre-draw refusal.** Only when no draw state and no basis exists for the slot: the Player-Character / player-control / Population-ledger boundary, cause ownership (never the actor's own state, kernel state or Causal Draw provenance), and each cause committed and pinned at its current version. A draw is irreversible, so a request that could never be admitted must not consume the slot's one opportunity.
2. **Causal Draw** (`CDR-01` in its exact order). The prior goes in as a specification: the stable draw key, the Named-Actor rule, the causes as the exact inputs, one opaque candidate per possibility with its authored weight. An empty, singleton or duplicated prior, or a malformed weight, is refused by the draw gate with its own code — **nothing is added, defaulted or turned into ordinary/C**.
3. **Interpretation.** The selected opaque candidate is read back to a marker by the owner.
4. **The owner's own write**, after the committed result: the basis carries that marker, reads the exact result fact/version and the causes, and depends on the canonical result group and the cause groups.

Every step is idempotent by identity. A technical retry after any committed Causal Draw state — precommit only, result only, the establishment, or the whole close — converges on the **same draw and the same establishment**; a committed seed is never replaced; an UNKNOWN outcome withholds new entropy from the store until it is reopened and reconciled (the Causal Draw guard, shared across adapters on one store). A changed prior or cause set under the same slot is `DRAW_IDENTITY_CONFLICT`, never a second draw. An independently established slot is `DRAW_NOT_REQUIRED_ALREADY_ESTABLISHED` with no entropy.

## Admission and load: the path cannot be bypassed or redrawn

IM-11 admission (and load verification, with the same derivation) requires of a `BOUNDED_PRIOR_RANDOMIZED` basis that:

- the draw is the stable draw of **this** actor and capability, its result is committed, read at its exact version, and its canonical result group is in `depends_on` (a missing result is refused; a read or dependency missing is refused);
- the prior was defined by the Named-Actor establishment operation, under the Named-Actor governing rule, from **exactly the pinned causes**, and every candidate is a lawful possibility in the owner's canonical encoding;
- the marker is exactly the owner's reading of the candidate the committed result selected — any other grade, EX or ungraded is refused;
- the stored form carries only a pointer and the marker (strict schema).

**Once Causal Draw evidence (precommit or result) exists for a slot, only the establishment that reads it may fill the slot**: a `CAUSALLY_DETERMINED` basis over existing draw evidence is refused at admission (and flagged on load by receipt order), so a committed draw cannot be sidestepped by the deterministic path. A Causal Draw record is never a legitimate cause of a mastery on either path. The basis remains create-only; there is no overwrite, second establishment or re-draw. The existing `CAUSALLY_DETERMINED` path is otherwise unchanged and never touches entropy.

## Judgment calls and open residuals (none resolves an open gate)

- **Candidate encoding.** The sources fix that candidates are opaque to the draw and meaningful only to the owner; they do not fix an encoding. The canonical encoding of the marker (`capability-candidate:v1:<base64url of its JSON>`) is the smallest derivation that needs no side table and no invented vocabulary, and it fixes spec identity per prior. If Blue intends another representation it is a localized change (and a different draw identity).
- **Draw-key components.** `causal_process_id`, `opportunity_id` and the operation name are technical encodings of CDK-01's four dimensions (CD1 §4 requires the substantive owner to construct them from subject/event state and the causal trigger). There is exactly one genuine opportunity per slot because the basis slot is create-only.
- **Owner-rule currency (CAL-08).** IM-01 is not implemented, so "authoritative/effective for creation of this prior" is implemented as identity with the registry-pinned `NAMED_ACTOR_RULE` at the F-027 spec lock, for the stable draw of an establishment slot. `NAMED_ACTOR_RULE` was deliberately **not** edited to cite CD1 §17: the rule is part of every committed Named-Actor fact's provenance and is compared on load, so editing it would invalidate existing saves. The prior's CD1 lineage is recorded in the sealed precommit instead.
- **Rarity and sparse-evidence rules are not adjudicated, exactly as for the deterministic path.** No source supplies a rule from causes to possibilities or weights, so the engine invents none: B/A/S candidates enter a prior only because the owner's authoring included them (§17 "causal support" stays an authoring discipline), weights are the owner's, and the engine guarantees only the structural half — no default prior, no default grade, no added or removed candidate, no weighting formula, no Potential, no percentage, EX never S+ (`{ ex: … }` is a distinct candidate meaning), ungraded never a below-C rung.
- **Escalation candidate 1 — a cause that advances between the committed draw and the establishment.** CD1 §12 says later input changes "are revalidated by the substantive owner when it attempts its own world-state write", but no source defines what the owner does when that revalidation fails, and a committed draw can neither be redrawn nor its prior changed (`DRAW_IDENTITY_CONFLICT`). This implementation fails closed (the establishment is refused as stale; nothing is invented), which leaves the slot unestablishable until a source defines the outcome. Smallest reproducible case: `tests/integration/actor-randomized-recovery.test.ts` ("a cause that moves on between the committed draw and the establishment").
- **Escalation candidate 2 — the CAL-08 port sees no candidates.** `OwnerRuleAuthority.isEffectiveForPriorCreation(rule, drawKey)` receives neither the candidates nor the weights, and the neutral layer checks no meaning. A caller holding the resolver context can therefore commit a draw under a slot's identity with a prior the owner would never author; the owner refuses to read it as its own establishment and its own request then conflicts. That is fail-closed, but it lets a stray draw block a slot. A fix needs a port or contract decision (pass the normalized prior to the authority) that belongs to the Causal Draw authority, not to this consumer.
- **Not implemented, fail closed:** PC capability, capability development/loss/Revelation, lifecycle transfer, Temporal stochastic mechanics, Legacy L-29/L-30/L-31, generic IM-01, provider/deployment work, PF-6/F-028, a separate RNG service, universal probability tables or power scaling, EX-as-S+, a Potential statistic. GitHub Issue #11 stays **open** (it closes only after exact-SHA Blue review of this implementation).
