# Diplomacy Framework Authoritative Core Backbone Foundation

Twenty-second bounded slice, built on the same commit, owner-registry, admission, persistence and recovery machinery as the Diplomacy External Recognition foundation (`docs/diplomacy-external-recognition-foundation.md`), the Externalized Claim / Dispute foundation (`docs/diplomacy-externalized-claim-dispute-foundation.md`), the Relation Edge foundation (`docs/diplomacy-relation-edge-foundation.md`) and the earlier owner foundations. It adds the Diplomacy owner's fourth persistent fact: one shared Diplomatic Framework for a durable multi-party external arrangement. **Initial authored establishment only.**

Governing source (exact pins live in `spec/f027/spec-lock.json` and the owner registry): **WS-008 Diplomacy / Inter-Faction Relations v1.1** (frozen F-027 pin `2026-09-24T07:01:45.312Z`) §§2.1–2.2, §4, §16 (the Framework minimum surface), §§19–24, §29.3, §29.5 and §29.7, with **F-016 Phase 2C** (pin `2026-09-21T23:21:44.154Z`) and **F-017** (pin `2026-09-25T23:42:27.802Z`), the last two only for the ownership and dependency boundaries relied upon.

A Framework is one shared object where one shared charter or instrument is future-causally sufficient and pairwise duplication is not. It is the Framework record itself: it is **not** a framework decision, a member decision, a Diplomatic Instrument, Clause or Binding Entry, a membership movement, a member-fault propagation, a commitment performance, a GIP institution, an Autonomous Collective, a Recognition, a Claim / Dispute or a Relation Edge index. It is created only by an explicit authored establishment; there is no all-pairs generator and no background scan.

**The decision boundary is an ownership boundary, not behavior.** WS-008 §29.5: a GIP-owned framework institution owns its internal procedure; a promoted autonomous collective resolves its own decision; only where neither exists may Diplomacy later apply the charter's decision rule mechanically to externally communicated member positions. This slice does none of those things. `collective_decision_rule_ref`, when authored, is stored as an opaque reference only; no vote, tally, quorum, chooser, interpretation, suspension, member-fault propagation or framework action is computed.

**Not implemented (out of scope, unchanged):** Channel / representation; Negotiation Record or procedure; Diplomatic Instrument, Clause, Binding Entry, Callable Right, compliance or performance; framework voting, collective choice, mechanical charter-rule execution, interpretation or adjudication, member-fault propagation; membership admission, exit, suspension, expulsion, succession, dissolution or any other post-establishment Framework transition; GIP institution / office / procedure creation or mutation; ACS promotion, collective agency or member decision ownership; party eligibility, representative competence or mandate validation; message dispatch, delivery, receipt, awareness or Epistemic packet creation; foreign-owner dereference, auto-created prerequisites or dependency-derived Framework conclusions; the Relation Edge derived `framework_refs[]` index or any other derived index (the Relation Edge persistent write contract is unchanged); pairwise Framework duplication; any timer, tick, scheduler, watcher, polling loop, RNG, seed or probability; and any workaround for GitHub Issue #11 (untouched).

## Identity, keys, lifecycle and idempotence

- **Identity is `framework_id` alone.** The key is `diplomacy/framework/<framework_id>`. The members, charter or instrument references, rules, shared commitments, lifecycle status and provenance are **not** identity dimensions. The Framework is stored once: no copy per member, relation, instrument, observer, population unit or locus, and no all-pairs or all-frameworks scan (WS-008 §29.7).
- **One slot per Framework.** A retry, a duplicate construction or a raw-store write reaches the same occupied slot, so no sibling record exists. Identical content under a different `framework_id` is a distinct record; nothing is merged or deduplicated. The recognition, dispute, relation and framework key spaces are disjoint.
- **ADVANCING, initial establishment only.** WS-008 describes later membership, lifecycle and action changes, so the kind is `ADVANCING`; this slice implements the first creation only. Diplomacy admission refuses every other change (`AMENDMENT_NOT_SUPPORTED`), and a second creation of an occupied key is refused by the store (`VERSION_CONFLICT`).
- **Retry converges, conflict fails closed.** Re-presenting the same intent is reconciled by identity (RC-16) to the original receipt. A different intent at an occupied `framework_id` — equal or different content — and the same intent with changed content are refused; the committed Framework is never rewritten.
- **No dependency is invented.** The Framework is Diplomacy-owned authored state, not a persisted conclusion derived from another owner's mutable state (§29.3), so its group reads and depends on nothing and the record carries no `dependency_refs[]`. A future Framework conclusion that derives from mutable foreign state needs its own separately bounded, dependency-aware slice.
- **No scan, clock or RNG.** Establishing a Framework reads nothing and writes only its own key; reading one is a direct keyed read; only the diagnostic load-time verifier lists facts, once per open.

## Interpretations recorded for review

1. **`framework_basis` is the weakest existing canonical singular authored representation.** WS-008 §16 fixes no executable subtype or closed vocabulary. It uses `SingularAuthoredValueSchema` (any canonical JSON scalar or object, the representation the Claim / Dispute `status` and Relation Edge singular fields already use); an array is multiplicity and is refused; no enum, taxonomy or alias normalisation is imposed.
2. **The three arrays carry no source-undefined rule.** WS-008 defines no minimum length, uniqueness, sorting, deduplication or reciprocal-copy rule for `member_refs[]`, `charter_or_instrument_refs[]` or `shared_commitment_refs[]`. Each is carried exactly as authored — empty, repeated and unsorted arrays are accepted and no element is reordered, removed or mirrored into another array. Each element is the repository's opaque `Id`; no referent class is fixed and nothing is dereferenced to admit the record.
3. **`membership_rules`, `entry_exit_rules` and `lifecycle_status` are singular authored values with no invented internal schema or closed set.** They use the same singular-value representation; no lifecycle value is defaulted and no cross-field rule ties a lifecycle value to the members or rules.
4. **`collective_decision_rule_ref` is conditional.** It is an optional singular opaque `Id`: absent stays absent (no default, no fabrication), present is carried exactly as authored. Its presence implies no GIP institution, ACS, vote or decision.
5. **`provenance_ref` is required and opaque.** It is a required singular `Id`, distinct from the engine's own rule / spec provenance metadata, and is never dereferenced. (The Relation Edge's `provenance_ref` is optional; WS-008 §16 lists the Framework's as a plain field, as the brief fixes it REQUIRED.)
6. **`framework_id` uses the repository's key-safe identifier rule** (`EntityId`, the same rule as the recognition, dispute and relation identities) because it is embedded in the canonical key.
7. **Create-time lifecycle values are authored, not transitions.** A Framework may be established already carrying any `lifecycle_status` value; the contract attaches no meaning and no cross-field rule to it, and no transition exists.
8. **The existing owner, a new facet and a new governing-rule citation; the others are untouched.** The Diplomacy owner is the existing IM-06 `diplomacy` owner. The citation records the WS-008 artifact and exact pin with clauses §§2.1–2.2, §4, §16, §§19–24, §29.3, §29.5 and §29.7 and the F-016 Phase 2C and F-017 lineage; no Recognition, Claim / Dispute or Relation Edge citation is reused or changed.
9. **No Relation Edge association.** The Relation Edge's derived `framework_refs[]` index stays absent from its persistent write contract: party / reference similarity between a Framework's members and an edge's parties is not an authoritative association seam, so none is read, matched or written.

These are recorded interpretations of the brief, not new rules; none adds a source-undefined executable restriction, and each is a candidate for the later Diplomacy work it belongs to.
