# Causal Draw Foundation (F-027-CD1)

Twenty-sixth bounded slice, built on the Campaign Continuity Foundation (`docs/campaign-package.md`) and the Canonical World Identity & Owner Foundation (`docs/canonical-world-foundation.md`). A **neutral Causal Draw** can now fix one genuinely residual uncertainty: a substantive owner supplies a bounded prior over **opaque candidate ids**, the layer **precommits 32 bytes of secure entropy**, selects exactly one candidate with a specified exact algorithm, and keeps the evidence as two **create-only provenance records** in the one existing journal. The layer **selects an opaque candidate id only**. It defines no candidate meaning, no causal weighting, no resulting world-state effect, no grade, no EX semantics and no owner-specific stochastic rule.

Governing implementation authority: **F-027 v1.0 composed with F-027-CD1 v1.0** (Causal Draw Implementation-Authority Addendum, Twenty-Fifth Blue Freeze, <https://app.notion.com/p/3ed20af901e08176abe1c203943294b1>), exact cleared native pin `2026-10-02T15:11:03.450Z`, which completed independent Red delta review with PASS and was verified unchanged at construction. The addendum is pinned in `spec/f027/spec-lock.json` under `implementation_authority_addenda` as a **composing** authority (`relation: COMPOSES_WITH`, `supersedes: null`): historical F-027 v1.0 is neither rewritten nor silently superseded, and every F-027 package, tranche and frozen-source pin and the Runtime Contract snapshot hash are unchanged.

## One canon: how it reuses IM-11 / IM-12 / IM-17

Nothing new is persisted outside the existing campaign package. Both records are ordinary `OwnerFact`s written through `store.commit`, so expected-version checks, RC-16 receipts, idempotent replay, unknown-outcome reconciliation, the hash-chained journal and package/load integrity are the ones in force. **The package format is unchanged; there is no second journal, queue, sidecar, scheduler or RNG service.** The adapter has exactly one `.commit(` call. The only edits to predecessor engine code are additive wiring: the registry gains the two kinds, `identityMismatch` handles them, `canonicalAdmission` dispatches the owner, and `verifyAll` also runs the verifier. No predecessor owner module (including the temporal coordinator and every Named-Actor module) was touched or names the layer.

## The operation: CDR-01 in order, then CDR-02

`draw({ specification, resolution })`, under the resolver context `role.resolver + permission.resolution.execute` (a precondition of the operation; publication is always `role.archivist + permission.canon.write`):

1. **Structural validation.** A lone surrogate or any malformed material → `DRAW_INPUT_INVALID`; then duplicate candidate ids → `DRAW_CANDIDATE_DUPLICATE`; an empty set → `DRAW_CANDIDATE_SET_EMPTY`; a singleton → `DRAW_NOT_REQUIRED_SINGLETON`. No hashing result, entropy or write.
2. **Normalize** (CDS-02) and compute `draw_key_digest`, `draw_id`, `spec_digest`.
3. **Committed result check.** Same `spec_digest` → replay (verified by re-derivation under the algorithm it committed under, never resampled); different → `DRAW_IDENTITY_CONFLICT`.
4. **Substantive-slot check**, by asking the substantive owner through its IM-03 typed interface. Established with no precommit/result → `DRAW_NOT_REQUIRED_ALREADY_ESTABLISHED`; established while a precommit exists, or claiming linkage (reads the result key / depends on the result group) to a result that is absent → `DRAW_STATE_CONFLICT`.
5. **Precommit resume.** Same `spec_digest` → recompute CDA-01 from the **committed** seed and commit/recover the one result (no new entropy; no revalidation of the owner rule or input currency, CDO-01); different → `DRAW_IDENTITY_CONFLICT`.
6. **New-precommit input proof only.** Unresolvable declared fact/version → `DRAW_INPUT_REF_UNRESOLVED`; a declared version that existed but is no longer current → `DRAW_INPUT_REF_STALE_AT_PRECOMMIT`.
7. **Only then** entropy (32 bytes, exactly; unavailable or short → `DRAW_ENTROPY_UNAVAILABLE`, nothing written), CAL-08 revalidation (owner rule still effective → else `DRAW_OWNER_RULE_STALE_AT_PRECOMMIT`; every input still pinned), and the create-only precommit; then the result.

A technical failure with unknown outcome is `UNKNOWN_OUTCOME` (RC-16): the adapter withholds all new entropy from that store until it is reopened and reconciled by the deterministic intent identity. A concurrent-precommit race commits exactly one seed; the loser discards its uncommitted seed, recovers the committed precommit, verifies the same `spec_digest` and continues from it. The substantive owner then writes **its own** result by reading the exact result fact/version and listing `result.group_id` in `depends_on`; the layer never writes that value.

## Judgment calls and open residuals (none resolves an open gate)

- **`input_refs[].committed_by` is not defined further by F-027-CD1.** It is implemented as the **group that committed that version** (the `OwnerFact` provenance `group_id`), the same reference kind the result's `precommit_committed_by` is (a group the result depends on). It is verified at the current version (`DRAW_INPUT_REF_UNRESOLVED` on mismatch). A superseded version cannot be re-attributed through the narrow store interface without scanning the journal, so it is reported `DRAW_INPUT_REF_STALE_AT_PRECOMMIT`. If Blue intends another meaning (an intent id, an owner role), it is a one-line change in `prior`/`adapter`, but it would be a different draw identity.
- **`owner_rule_ref` currency has no production source yet.** CAL-08 needs a judgment that a rule is "authoritative/effective for creation of this prior"; nothing in the repository can make it (IM-01, the specification and authority loader, is not implemented). The adapter therefore **requires** an `OwnerRuleAuthority` and an IM-03 `SubstantiveSlotInspector` per substantive owner (there is no default and no fallback; an owner with no inspector is `OWNER_NOT_REGISTERED`). Tests supply synthetic ones. The WS-016 consumer slice supplies the real Named-Actor ones (twenty-seventh slice, `docs/actor-randomized-establishment-foundation.md`). Both are consulted by the adapter immediately before publication, because admission is pure over (group, state) and cannot call a foreign owner.
- **Authority.** The resolver context is checked as an operation precondition (a non-matching or non-JSON context is `AUTHORITY_DENIED`) before step 1; it adds no gate among steps 1–7 and reorders none. Replay therefore also needs it. CDR-01 does not state otherwise.
- **Precedence inside step 1** follows the order the addendum lists (malformed, duplicate candidate, empty, singleton); an exactly duplicated input ref is "malformed". An unresolvable input outranks a stale one.
- **Refusal names beyond the addendum's list:** `DRAW_INTEGRITY_FAILURE` (the class §12 names but does not code), and the repository's existing `AUTHORITY_DENIED`, `OWNER_NOT_REGISTERED` and store codes.
- **SEALED** uses the repository's existing create-only lifecycle value; no enum was added.
- **No operational resource ceiling** (candidate count, weight length) is enforced; if one is later authorized it must fail closed before precommit.
- The Runtime Contract snapshot (`runtime-contract.md`, the save-compatibility key) and the open-gates snapshot are byte-identical; the register's lock hash and the generated build spec identity were regenerated. Existing saves still load.
