## The derivation

1. **Active viewpoint first (I-001 §4 step 1).** The committed Role Registry binding `role-registry/binding/role.player_character` must name the requested recipient _now_ (`recipientBoundaryViolation`, reused unchanged: no Existence-Contract-only PC, no other or unbound identity, no Population ledger).
2. **Active-PC path only.** The engine-side event is read **only to classify the recipient path**: it must assert `recipient_role: "role.player_character"` for that recipient. A packet formed for a Named-Actor identity is never the PC's, even if that identity is bound later (the existing "no cross-handover reconstruction" boundary). Nothing of the event reaches the output.
3. **The actor-safe packet is the only content source (F-014D §2.1, §18).** The packet must be the committed `epistemic_access` fact at its derived key, class `epistemic.actor-accessible`, and exactly the event's received route and payload (payload, attribution, channel, arrival basis); a tampered packet is no arrival. The projection is copied field by field from the packet. The Sealed Engine Provenance, the capability, the source and the event identity are never read into the output.
4. **Current arrival (the no-universal-memory boundary, I-001 §11).** See below.
5. **Compose the smallest faithful projection (I-001 §4 step 4, §9, §10).** The `contact` envelope is separated from the received `payload`; the Presented Source Attribution is preserved exactly (it may be false and is never the true source); the payload is preserved exactly and never corrected against hidden canonical truth. Representational intelligibility is a _precondition_ of the packet existing (F-014D §5 step 4), so neither the result nor the capability that established it is projected. No urgency is invented (the packet defines none), no interpretation is attached, and the canonical time coordinate is withheld (it is not the PC's perceived granularity: no false precision, I-001 §4 step 6).

Every failure is the **same** refusal (one code, one message, no details), including an internal failure, so neither an error nor its shape distinguishes a hidden fact from an absent one (I-001 §4 step 3; RC-14). No timing equalization is claimed or tested.

## Current arrival: derived from existing Temporal state, not a new rule

I-001 §11 forbids universal recall: "a prior fact may be re-presented only when there is a current lawful basis … or fresh communication of the fact". I-001 §9: "present only what has actually arrived". F-014B §4: "AS-OF-NOW reads the value established at the current resolution point". The packet is a durable sealed fact, so _its existence_ cannot be the test (that would be exactly the universal recall §11 forbids). The one existing notion of "the current resolution point" is the committed Temporal state: `temporal/state.last_transaction`, the latest sealed player-facing resolution transaction, whose `actual_stop` is the canonical time.

An arrival is therefore **current exactly when its packet was formed under the durable authority of that latest sealed transaction**, verified from committed records only: the transaction recorded the formation stage; the stage's group is the packet's committing group; the transaction wrote this packet version; and the formation group's own last dependency is that transaction's `transaction-authority-group` (the authority the transaction opened before any of its stages could commit). The last check matters: the coordinator also _adopts_ an already-committed stage by identity into a later transaction's stage list (a later consequence that re-declares the formation), so "recorded in the latest transaction" alone would let any later consequence make a historical packet current again. The test for that hole (`integration/i001-event-signal-projection.test.ts`, "re-declares and adopts") fails when the authority check is removed.

Consequences, all deliberate and all derived rather than configured: a packet formed by an earlier transaction stays stored and byte-identical but projects nothing (storage alone is no recall basis); an arrival is not presentable until its transaction is sealed; an unrelated later transaction ends the arrival's currency; a saved and reloaded campaign projects the same current arrival and never resurrects a historical one. **No window, tolerance, counter, retention flag, "seen"/"expired" marker, replay buffer, retrieval index or memory mechanism was added, and nothing is written to track any of it.** The human player's own memory remains the default recall surface (§11); a _lawful_ recall route (retained carrier, aide, journal, enhanced memory) belongs to later work that owns those mechanisms.

**Interpretive anchor for review.** Reading "current arrival" as "formed by the latest sealed resolution transaction" is the one interpretive step in this slice. It uses only existing committed Temporal evidence and the strictest reading available (it can only refuse more, never present more), and the authority texts do not define a different currency window. Should Blue/Red rule a different meaning, only step 4 of the derivation changes; nothing else depends on it.
